1 # Symnav Daemon Follow-ups Functional Spec
2 
3 ## Goal
4 
5 Six behavior changes surfaced by the architecture reviews and deferred until after the daemon restructuring in `daemon-architecture-functional-spec.md`. Each amends `daemon-functional-spec.md`; that document stays the source of truth for everything not named here. This is not a rewrite of routing, admission, or delivery, and not a change to any navigation command's output. This spec defines product behavior only; implementation choices live in the phased plans.
6 
7 ## Primary User
8 
9 Same as `daemon-functional-spec.md`: an AI coding agent issuing `symnav` commands, plus the human running `daemon start|status|stop`. Default experience is unchanged; the changes below remove five ways a daemon can degrade silently and evaluate one simpler election mechanism.
10 
11 ## Core Guarantees
12 
13 All guarantees in `daemon-functional-spec.md` hold. Two are sharpened.
14 
15 ### Slow is not dead, but silent forever is abandoned
16 
17 A daemon warming up for hours stays valid as long as it keeps reporting progress. A daemon that stops reporting progress while its process stays alive is eventually treated as abandoned.
18 
19 ```text
20 A starting daemon that has reported no progress for the startup silence bound is abandoned:
21 its ownership is cleared and the next eligible command may trigger a replacement.
22 ```
23 
24 This is a bound on silence, not on warm-up duration. A healthy twenty-minute or two-hour warm-up that keeps reporting progress is never abandoned. There is still no healthy-startup timeout.
25 
26 ### Bounded memory for accepted work
27 
28 Every structure that records accepted requests is bounded. A daemon serving requests for days does not grow because of its own bookkeeping.
29 
30 ```text
31 Once a result is acknowledged, or its retention period ends, nothing about that request remains in daemon memory.
32 ```
33 
34 There is no unbounded-retention override.
35 
36 ## Scope
37 
38 ### Included
39 
40 - Accepted-request ledger eviction.
41 - Startup silence bound.
42 - `daemon start` readiness proved on the control plane.
43 - Endpoints under the state directory.
44 - Selection-aware source-cache retention.
45 - Election by socket bind (evaluation; adopted only if it passes the existing daemon suites).
46 
47 ### Excluded
48 
49 - Any change to navigation command output or exit codes.
50 - New flags or environment variables. The silence bound and retention period are policy values with no user tuning.
51 - Changing the `30 minutes` idle exit, routing table, or FIFO execution.
52 - Changing `daemon status` line format beyond what a state change already produces.
53 
54 ## Interaction Model
55 
56 Unchanged. `symnav <command>`, `symnav daemon start|status|stop`, `--cwd`, `SYMNAV_DAEMON=0`, `SYMNAV_STATE_DIR` behave as specified in `daemon-functional-spec.md`.
57 
58 ## Output Format
59 
60 Unchanged. `daemon start`, `daemon status`, and `daemon stop` print the same lines. The only observable differences are *when* `daemon start` returns and *which* state `daemon status` reports for an abandoned startup.
61 
62 ## Cross-cutting Concerns
63 
64 ### Policy values
65 
66 | Value                      | Default     | Reason                                                         |
67 | -------------------------- | ----------- | -------------------------------------------------------------- |
68 | Startup silence bound      | `6 hours`   | Longer than any observed healthy warm-up gap; short enough that a hung daemon recovers within a working day |
69 | Acknowledged-entry removal | immediate   | Nothing references an acknowledged result                       |
70 | Unacknowledged retention   | `5 minutes` | Matches operation-trace retention so reconnect evidence and ledger expire together |
71 
72 Values live in the daemon policy record; tests override them, users cannot.
73 
74 ### Ordering
75 
76 Endpoint relocation and the election evaluation change how a daemon is found and owned; they land after ledger eviction, the silence bound, and control-plane readiness, which do not.
77 
78 ## Ledger Eviction
79 
80 **Purpose.** Stop the accepted-request ledger growing for the daemon's lifetime.
81 
82 **Produces.** An acknowledged request disappears from the ledger at acknowledgement. An accepted request whose client never acknowledges disappears when its operation trace expires. Memory reported by `daemon status` stays flat under sustained request churn with no workspace changes.
83 
84 **Does not produce.** Early removal of a request whose result has not been delivered. A duplicate execution: a reconnect inside the retention period still attaches to the existing result.
85 
86 **Examples.**
87 
88 - 10,000 `overview` requests over a day, all acknowledged: ledger holds zero entries afterwards.
89 - A client disconnects after acceptance and never returns: entry and spool are gone `5 minutes` after completion.
90 - A client reconnects `4 minutes` after disconnect: it receives the stored result; at `6 minutes` it receives a not-found rejection and executes locally, since admission was never proven for that reconnect.
91 
92 **Edge cases.** Retention is measured from completion, not acceptance. A request still queued or executing is never evicted.
93 
94 ## Startup Silence Bound
95 
96 **Purpose.** Recover from a warm-up that hangs without crashing.
97 
98 **Produces.** A daemon in `starting` that has reported no progress for `6 hours` is abandoned: its record is cleared, `daemon status` no longer lists it, and the next ordinary command triggers a new warm-up. The abandoned process is terminated the same way `daemon stop` terminates a daemon.
99 
100 **Does not produce.** Abandonment of a starting daemon that keeps reporting progress, however long it takes. Any change to ordinary-command latency: commands keep answering locally while a daemon is starting or abandoned.
101 
102 **Examples.**
103 
104 - Warm-up of a 10× workspace takes `2 hours` with steady progress: never abandoned; `daemon status` shows `starting 2h`.
105 - Warm-up deadlocks after `3 minutes`; process stays alive: for `6 hours` `daemon status` shows `starting`; afterwards the record is gone and the next command starts a replacement.
106 - Explicit `daemon start` attached to a warm-up that is then abandoned: returns a startup failure, exit `1`, naming the silence bound.
107 
108 **Edge cases.** Machine sleep pauses the clock the bound is measured on; wall-clock jumps do not abandon a daemon. Concurrent commands observing an abandoned record trigger exactly one replacement.
109 
110 ## Control-Plane Readiness
111 
112 **Purpose.** Make `daemon start` return as soon as the daemon can accept work, independent of queued navigation.
113 
114 **Produces.** `daemon start` reports ready when the daemon's worker is initialized and admission is open. On an already-ready busy daemon it returns `already running` at once.
115 
116 **Does not produce.** A wait behind queued or executing navigation requests. A readiness claim for a daemon whose worker has not finished initializing.
117 
118 **Examples.**
119 
120 - Daemon ready, currently executing a `40 s` `refs`: `daemon start` returns `already running` within the status response target of `1 second`.
121 - Daemon starting, `4 minutes` remaining: `daemon start` waits `4 minutes`, then prints `ready`, without any navigation request having run.
122 
123 **Edge cases.** A daemon that becomes ready and then fails its worker before `daemon start` returns reports a startup failure, not ready. Concurrent explicit starts all return when the same daemon becomes ready.
124 
125 ## Endpoints Under the State Directory
126 
127 **Purpose.** Make a state location fully self-contained.
128 
129 **Produces.** The daemon's local endpoint lives under the state directory alongside registry, logs, and spools. Removing a state directory removes everything belonging to its daemons; a daemon whose state directory is removed while running shuts down as it does today on workspace deletion.
130 
131 **Does not produce.** Cross-user endpoint visibility: permissions on the state directory continue to isolate users. Any change to `SYMNAV_STATE_DIR` semantics.
132 
133 **Examples.**
134 
135 - `SYMNAV_STATE_DIR=/tmp/session-a symnav daemon start`, then `rm -rf /tmp/session-a`: no socket or pipe remains anywhere on the machine.
136 - Two state locations for the same workspace: two endpoints, in two directories, never colliding.
137 
138 **Edge cases.** Platforms with a path-length limit on endpoints fall back to a short endpoint name derived from the state directory identity, still under that directory where the platform allows a filesystem endpoint at all. On platforms where endpoints are not filesystem objects, the endpoint name incorporates the state directory identity so removal semantics hold by construction.
139 
140 ## Election by Socket Bind
141 
142 **Purpose.** Evaluate replacing the file-lease election with the operating system's rule that one process can own an endpoint.
143 
144 **Produces.** An evaluation with the existing e2e daemon and parity suites as the oracle. If adopted: a daemon binds its endpoint as its first act; concurrent starters spawn children that lose the bind and exit before loading any workspace state; a client that finds a dead endpoint clears it and triggers a replacement; the registry records only where a daemon is, not who is allowed to start one. Every guarantee in `daemon-functional-spec.md` still holds, including one durable warm-up per workspace and slow-is-not-dead.
145 
146 **Does not produce.** A behavior difference visible in any spec example. More than one ready daemon per workspace and state location at any moment.
147 
148 **Examples.**
149 
150 - Ten cold commands at once: up to ten short-lived processes start, one binds and warms, nine exit within the startup budget; all ten commands answer locally. `daemon status` shows one daemon.
151 - Daemon crashes leaving a stale endpoint: next command finds it unreachable, clears it, triggers one warm-up, answers locally.
152 
153 **Edge cases.** Two clients clearing the same stale endpoint at once still yield one bound daemon. A daemon that binds and then fails during warm-up releases the endpoint on exit so the next command can retry.
154 
155 **Outcome.** If the evaluation fails a suite or violates a guarantee, the file lease stays and this section is withdrawn.
156 
157 ## Selection-Aware Source-Cache Retention
158 
159 **Purpose.** Avoid discarding unchanged sibling source bytes when a retained command refreshes only its selected file.
160 
161 **Produces.** A selection refresh updates cached revisions for supplied files without evicting omitted files from the last authoritative workspace refresh. A later workspace refresh still replaces the authoritative revision set, invalidates changed bytes, and removes deleted files before a whole-workspace semantic query runs.
162 
163 **Does not produce.** Eager metadata or source reads for omitted siblings during a selection command. A stale navigation answer. Cache ownership of workspace discovery or project membership.
164 
165 **Examples.**
166 
167 - A full refresh caches `src/a.ts` and `src/b.ts`; an `overview src/a.ts` selection retains cached bytes for `src/b.ts` without statting or reading it.
168 - A later `refs` turn finds `src/b.ts` unchanged during its workspace refresh and reuses the retained bytes.
169 - A later workspace refresh finds `src/b.ts` changed or deleted and invalidates its old bytes before navigation starts.
170 
171 **Edge cases.** A selection with a changed absolute path or change token invalidates the prior bytes for that supplied file. Omitted entries remain bounded by the most recent authoritative workspace snapshot.

173 ## Summary
174 
175 | Change                        | One line                                                                    |
176 | ----------------------------- | --------------------------------------------------------------------------- |
177 | Ledger eviction               | Acknowledged entries removed at once; unacknowledged expire with their trace |
178 | Startup silence bound         | A starting daemon silent for `6 hours` is abandoned and replaced             |
179 | Control-plane readiness       | `daemon start` returns when admission opens, not after queued navigation     |
180 | Endpoints under state dir     | Removing a state directory removes its endpoints                             |
181 | Selection-aware source cache  | Selection refreshes retain unchanged omitted bytes without eager sibling reads |
182 | Election by socket bind       | Evaluate OS-enforced single owner in place of file lease; adopt only if suites pass |
