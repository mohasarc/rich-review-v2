knew too much.

03

Order determines which observations can happen.

D07
Use four ordered, lazy routing guards
STATED

Record present → not starting → version → responsive. Read and observation are memoized; a decision prevents every later guard and its effects.

reason + evidence ↗
D08
Keep the route and local-execution distinctions
STATED

Disabled, absent, starting, or recovering run cold; ready/busy run warm; dead/incompatible fall back. Only absent/fallback routing decisions trigger independent warmup. Local attempts get fresh executors. Errors and exact-process cleanup keep their distinct routes.

reason + evidence ↗
D09
Compose lifecycle once, with a separate status timeout
STATED

Disabled blocks start; status and stop still operate. The host supplies the readiness command, which still runs through execution. Control failures reject to the host wrapper.

reason + evidence ↗
04
A missing answer is not permission to replay ↗

The client owns the boundary between a retry and a second execution.

D10
Let transport retry-safety authorize fallback
STATED

A retry-safe warm submission failure gets one local fallback. An uncertain or accepted failure stays warm and produces a controlled failure instead of replay.

reason + evidence ↗
D11
Own warm output capture inside the package
STATED

Each transfer gets a fresh policy-limited capture, using memory then an OS-temporary spool. The returned output still has records() and dispose(); the host does not provide capture factories.

reason + evidence ↗
D12
Own failure output and malformed-result cleanup
STATED

Resource, response-capacity, and incomplete-request failures become stderr + exit 1. A missing output or non-integer exit code is incomplete; any available malformed output is disposed.

reason + evidence ↗

Centralize authority while preserving the old timing and authentication rules.

Validate adopted coordinates inside the coordinator
UNEXPLAINED

The renamed coordinator takes coordinates, a serving port, a workspace-exists callback, and an explicit clock. Identity mismatches fail before component setup; that placement has no stated rationale.

reason + evidence ↗
D14
Give registry startup equality one owner
STATED

Callers request named identity/instance/token/PID checks. One predicate compares the requested coordinates; exact-owner cleanup also compares timestamps and revision.

reason + evidence ↗
D15
Pin the existing authentication order and exceptions
UNEXPLAINED

Execution checks protocol/instance before token. Identify/terminate/kill use identity credentials; ping/stop still omit token checks. No reason for that asymmetry was found.

reason + evidence ↗
D16
Use a daemon-owned clock API
STATED

Daemon mechanisms stop using telemetry clocks and raw time sources. Wall time still owns persisted/lifetime deadlines; monotonic time owns elapsed execution and queue measurements.

reason + evidence ↗
D17
Defer readiness- and completion-based idle timing
STATED

Idle time starts in the constructor and resets at navigation acceptance. Long startup or a long completed turn can exhaust it. Ready/completion resets are written down as future behavior.
