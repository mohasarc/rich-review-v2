01 / DECISIONS CARRIED BY THE CONTRACTS

What the caller inherits

“Stated” means a reason was found.
“Unexplained” means none was found in the inspected inputs.

P1
STATED
Make policy supply mandatory at consumer construction

The PR says omission must not recreate local defaults. The spec assigns every threshold one owner.

Inspect the evidence ↗
B
Optional numeric arguments and constants configure app-owned mechanisms, alongside the existing snapshot.
A
Consumers take required policy sections. Removed constants and the CLI resource factory have no production compatibility overload. Clocks, storage, factories, directories and write fragmentation remain injectable; classes stay in apps/cli.
P2
STATED
Carry one output budget through every representation

The PR explicitly covers output capture, spooling, framing and worker validation; the policy record gives the capacity reasons.

Inspect the evidence ↗
B
64 KiB chunks, 256 KiB inline, 256 MiB result, 512 MiB aggregate; several fixed or optional local sources.
A
Same production defaults from output policy. Storage.records, decodeFileRecords, encode/decode and worker response validation require a chunk cap. Raw in-memory decodeRecords still has no policy parameter.
P3
STATED
Choose timeout by the transport’s purpose

The PR distinguishes status observation from ordinary execution-status requests.

Inspect the evidence ↗
B
Status command constructs a transport with requestTimeoutMs: 100; ordinary default is 250 ms.
A
Constructor purpose selects 100 ms status-observer or 250 ms ordinary. Admission remains 5 s. No accepted-completion deadline is added; the timer is disabled at acceptance.
P4
STATED
Keep execution reattachment and result resume separate

The PR says each reattached execute attempt has its own fetch-resume allowance.

Inspect the evidence ↗
B
One reattachment in an outer catch; one boolean resume guard inside executeOnce.
A
Numeric counters default to one each. Reattachment resubmits the same authenticated request; each executeOnce starts resumeCount at zero. A failed fetch rejects completion; the fetch path itself does not schedule a further fetch.
P5
UNEXPLAINED
Change which reattachment error escapes

No reason found for this error-selection change in the PR, commits or policy record.

Inspect the evidence ↗
B
If reattached acceptance or completion fails, the catch throws the original completion error.
A
Failure to obtain a reattached receipt still throws the current completion error. Once a receipt exists, a later completion failure is handled on the next loop and may become the reported error.
P6
STATED
Centralize distinct lifecycle timers and child retries

The policy record gives a reason for each cadence and deadline and explicitly leaves healthy startup untimed.

Inspect the evidence ↗
B
15 s ownership grace, 100/10/20 ms startup cadences, one child retry; stop/signal/idle numbers live near use.
A
Same defaults from startup/shutdown. ensureRunning retries child-exit or lost-warmup up to policy limit. Stop reserves min(maximum reserve, floor(stop window / 2)); SIGTERM then SIGKILL remain. Unused startupTimeoutMs is deleted.
P7
STATED
Use the snapshot for memory and the replacement circuit

The spec and policy record put the memory recipe, pressure thresholds and anti-churn circuit under daemon policy.

Inspect the evidence ↗
B
CLI re-derives a resource record; WorkspaceDaemon can accept independent memoryCapBytes/resourcePolicy.
A
Use resources directly, including worker MiB limit and ready/status hard-RSS reports. Keep soft/resume hysteresis, generation fencing and boundary scheduling. Supervision 250 ms, worker sampling 25 ms, two replacements per 10 min before drain.
P8
STATED
Consume diagnostics policy without changing failure isolation

The PR names logging and trace retention as consumers; the policy record explains bounded diagnostic retention.

Inspect the evidence ↗
B
Logger and daemon choose queue, rotation, backup and trace values locally.
A
10 MiB logs / four backups / 1,024 queued events and five-minute / 1,024 disconnected traces come from policy. Closed event schemas, correlation hashing, dropping and best-effort storage behavior remain.
P9
STATED
Move numeric test knobs into seven adapters

The PR says tests need small thresholds without reopening production tuning seams.

Inspect the evidence ↗
B
Tests construct runtime classes with legacy numbers; some force disk storage with inlineBytes: 0.
A
New helper classes translate knobs via DaemonPolicyTestFactory or forward explicit policy. Valid snapshots enforce chunk ≤ inline ≤ result ≤ aggregate and positive chunk size. Test calls and benchmark imports move to helpers.
P10
UNEXPLAINED
Leave a few low-level numeric seams and normalize test values

No specific reason found for retaining the explicit registry grace override or these adapter translations; the broader adapter choice is stated separately.

Inspect the evidence ↗
B
Registry can accept explicit grace; test transport inline sizes can be tiny; workspace tests can pass memoryCapBytes.
A
Registry still accepts graceMs. Test transport raises inline bytes to at least a chunk and creates a requested output directory; workspace helper can map zero inline to half a result cap, lower chunk/result sizes, and still accepts memoryCapBytes without reading it. Codec/storage caps remain raw required numbers.
P11
UNEXPLAINED
Change the test witnesses alongside the production seam

The PR promises threshold/retry preservation and names test adapters, but gives no specific reason for each deleted case or changed fixture value.

Inspect the evidence ↗
B
CLI resource suite pins memory derivation and its exported 250 ms constant; capture parity spills at 1 byte; spool tests use zero inline.
A
Delete the old resource-policy block (five parameter rows plus constrained-memory and cadence cases); daemon-package policy tests already cover the recipe, with a 1-byte boundary instead of 256 MiB. Capture parity now uses 32 bytes; zero-inline spool cases cross positive thresholds with extra records. Add policy, one-byte chunk, timeout, zero/two child-retry and reattach/fetch checks; expand retired-name meta-tests.
P12
UNEXPLAINED
Parse policy in the parent before constructing the worker

Worker chunk validation is explicitly in scope, but no reason is given for moving malformed-snapshot failure to parent construction as well as worker startup.

Inspect the evidence ↗
B
Parent starts the worker with the serialized policy; the worker entry parses it.
A
NodeDaemonNavigationWorker first calls DaemonPolicy.fromSerialized to obtain maximumChunkRawBytes, then creates Worker. An invalid serialized snapshot can now throw synchronously before a thread is spawned.

Manifest exists; transfer interrupted	Boolean resume guard in executeOnce	Resume count in executeOnce; default 1
