01
Lifetime moves. Query ownership stays.

Core now supplies the lifetime class. Each TypeScript query service owns one scope and six isolated handles: definitions, reference locations, call targets, callers, callees, and position definitions. Algorithms and key spaces stay in TypeScript; its existing dependency on core remains.

Stated: core owns generic lifetime; independent key/value spaces need separate handles. Unexplained: composition via a scope instead of the spec’s proposed extension shape.

02
A lookup keeps the exact factory value.

Same key + same handle + same turn returns the stored value. Five stores use symbol-identity keys; position definitions use path + offset. Empty results and undefined count as entries. Rejected promises remain cached; a synchronous factory throw stores nothing, so the next call retries.

Stated: preserve existing key, identity and failure behavior; Map.has admits cached undefined. No new retry or cancellation policy is added.

03
Clearing forgets entries. It leaves held promises alone.

beginTurn and scope release synchronously clear all handles, which remain reusable. A caller’s old promise can still settle; its settlement cannot overwrite a newer entry. This identity pattern is preserved in the base/head service recording. The ritual isolates one handle; it does not model garbage collection or cancel work.

Stated: preserve promise/value identities and failure behavior. The new core test pins old settlement versus a new entry; no separate reason for that exact test case was supplied.

05
Only a successful refresh begins the next turn.

Backend refresh clears after the awaited refresh work succeeds. A failed refresh keeps the successful turn’s entries. The exported service now takes readonly files rather than the whole snapshot.

Stated: failed refresh must preserve the current successful turn. Unexplained: why narrow the public beginTurn argument in this layer. The clearing order is preserved, not newly invented.

06
Cache clear and project cleanup have separate endings.

Both versions clear before project cleanup. Head adds await through backend → service → project graph: pending cleanup keeps backend release pending, and cleanup rejection reaches that caller. Base returns early. The graph accepts async cleanup; the concrete TypeScript project cleanup here is synchronous.

Stated: clear first so released semantics are unavailable during pending or rejecting cleanup. Unexplained: reconciliation of the new completion/rejection behavior with the spec’s behavior-preservation rule. The ritual’s finger release means injected work settlement, not this cleanup call.
