  THE COMPLETE STOPPING LAYER
  Eight things the circuit tells you.
  The board, legend and all eight readings are the complete layer. Open a reading or component for mechanism and pinned evidence.
  01
  The mechanism changes its package.
  Main keeps this circuit in apps/cli. #148 stages the daemon package; #149 connects the shipped CLI to DaemonClient. CLI keeps argv and workspace discovery; daemon owns routing, admission, transport and recovery.
  Stated · separate mechanism ownership from the host invocation switch.
  ↗
  02
  A route is chosen before submission.
  Ordered lazy checks stop at the first route: record present → not starting → version compatible → responsive. Warm goes to the socket; cold/fallback go local. Selected startup runs independently and never switches the chosen route.
  Stated · the first routing decision must prevent later side effects.
  ↗
  03
  The first failing gate names the rejection.
  Token → worker → resources → queue → duplicate. Token mismatch disconnects with no rejection frame or resource sample. Not-ready, pressure and draining permit local fallback; incompatible does not. A matching duplicate reuses accepted state; a conflict leaves it untouched.
  Stated · visible, testable order and nonmutating compatibility. Unexplained · why this exact original priority was chosen.
  ↗
  04
  A write is not an acceptance receipt.
  Transport tracks not-submitted, submitted-unconfirmed, and accepted. Only the first state proves no submission. Silence after a write grants no local retry. Framing, validation and socket I/O have separate owners; reply coordinates must match.
  Stated · preserve delivery and authentication classifications while splitting transport responsibilities.
  ↗
  05
  The code table owns the retry bit.
  Local permit = not-submitted OR an authenticated, consistent rejection whose code is not-ready / resource-pressure / draining. #134 tightens main’s trusted wire boolean: incompatible + true is corrupt, never replay permission.
  Stated · contradictory frames must be corrupt rather than replayable.
  ↗
  06
  Accepted work cannot power local replay.
  Acceptance keeps request identity and disables the admission timer; completion has no deadline. The outer terminal codes are worker-exit, controlled-resource, response-capacity, stopping, internal—distinct from inner worker failures. Each yields a controlled result, with no local execution.
  Stated · one outer vocabulary; accepted terminal failures never replay work.
  ↗
  07
  Recovery has two separate allowances.
  With a manifest, result-fetch resumes at the next record offset in the same capture. An authenticated accepted close can reattach the identical execute request with a fresh capture. Current limits: 1 fetch per attempt, 1 reattachment per request. Clean fetch exhaustion → corrupt; reattachment failure retains the first accepted close. Verify output, then ACK before completion.
  Stated · independent recovery scopes and capture lifetimes. Unexplained · quantitative basis for choosing exactly one.
  ↗
  08
  This is a bounded teaching instrument.
  Source-derived simulation: admission and retry gates execute frozen source; socket/host actions are modeled. Thirteen actual client probes use scripted I/O. 147 focused source tests passed. Added guard/contradiction and recovery tests support this slice; the full stack and human comprehension are untested here.
  Stated · focused ownership/precedence and preserved recovery oracles. No correctness verdict or whole-stack parity claim.
