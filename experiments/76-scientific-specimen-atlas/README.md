# scientific-specimen-atlas

## Entry point

Open [index.html](index.html) directly, offline:

```sh
open ~/projects/rich-review-v2/experiments/76-scientific-specimen-atlas/index.html
```

**What survives a fresh start?** compares two prepared specimens. Follow sections 01–03, use the selective stain to isolate a lifetime class, then change an intervention in the recorded experiment. Each of the ten findings links to its structure notes and returns to the same finding. Source receipts open locally; Escape closes them and restores focus. Prediction answers reveal locally. Nothing is stored.

No install, server, network or live worktree is needed to read the page. On narrow screens the three sections stack vertically. JavaScript enables the figures and experiment controls; the complete finding register, structure notes, prediction answers and [source book](evidence.html) remain readable without it.

## Subjects

pr-127 and pr-131. The narrow subject is **selective reset: which state survives a lifetime boundary?** This is not a whole-PR explanation or decision census. In #127 it follows cache handles, entries and caller-held promises. In #131 it follows the required delivery slice, per-attempt fetch state and outer reattachment state. Other policy consumers, timing purposes, resource thresholds and daemon mechanisms are outside this specimen.

## What I tried

I considered a lifetime timeline and a policy-capture atlas, then chose serial sections of **nested scope** so the small and wide PR share a visual grammar. This avoids repeating the identity matrix in 36, orthogonal navigation in 37, release spring in 53, microscope camera in 68 or policy distribution figure in 62.

The first render used marks that were too small and three horizontal sections on phones. Screenshots led to larger glyphs and labels, rounded owner enclosures, real dashed reset boundaries, and vertically faceted phone sections. A cleared-but-not-yet-queried cache checkpoint initially looked like a replacement entry; the recorder now verifies zero entries there and the chart uses an open mark. Release tables now show the pending checkpoint as well as settlement.

The custom fetch-allowance experiment is a useful negative result: allowance three produces **one fetch**, then `corrupt`, when the resumed stream ends incomplete. The first fetch has no repeated-fetch loop on that path. A separate recording preserves the later-error difference between base and head. No complete representation was abandoned. The initial recorder used the wrong symbol-identity shape; it was corrected before any displayed observations were captured.

## What I would drop

Some repeated owner labels in the serial sections could shrink for an expert audience. The prose structure notes are longer than the visual plate; error selection earns that space, but the ownership explanation partly repeats what the plate already shows. The phone layout trades horizontal comparison for a substantially longer page.

## What I would do next

Give readers the plate alone and ask them to predict which handle, promise and counter survives each boundary. Compare their explanations with those elicited by a conventional before/after diagram; no human comprehension trial has been performed.

## Visual-variable legend

| Variable | Meaning | Limit |
| --- | --- | --- |
| Teal / rust on the plate | Original or retained scope / contents belonging to a newly begun scope | Pigment is a lifetime class, not a memory address or object identity across builds. |
| Enclosure and nesting | Who holds the state; inner dashed enclosure marks the reset scope | Geometry is a prepared-section analogy, not physical memory or a biological measurement. |
| Rectangle / circle / diamond | Reusable structure / value or promise / counter | The output glyph groups receiver and output for the attempted transfer; the label names output. |
| Position outside the cache scope | The caller still holds the old promise | It does not imply a different process or a garbage-collection measurement. |
| Repeated section position | The same role at the next observation checkpoint | Spacing is not elapsed time; section count is not a retry budget. |
| Selective stain | Isolate retained, fresh or outside state without hiding the findings | This is an inspection control, not live execution. |
| Cache laboratory y-position | Number of definition searches actually started | Empty controlled workspace; no duration or semantic answer quality is measured. |
| Filled teal / rust / open cache point | Original entry / replacement entry / cleared and still empty | Handles are checked independently; a new entry is not a new handle. |
| Delivery laboratory x-position and shape | Recorded execute/fetch request counts; square = execute, diamond = fetch | Teal/base and rust/head are explicitly relabeled for this chart. Execute requests are not proof of command reruns. |

The six cache abbreviations and both counter denominators are decoded beside the figures. No quantity is encoded in enclosure size.

## What the form teaches better or worse

The prepared sections let the eye follow **one retained enclosure and one replaced interior at the same time**. Registering the two specimens makes the shared principle visible: a new inner scope does not reset its enclosing lifetime. The outside promise also makes “cleared” visibly different from “cancelled.” Staining gives the reader a way to inspect that distinction without switching to a different diagram.

A conventional before/after diagram would show the package move more economically. It would also be easier to scan on a phone. Serial sections do not naturally show which error escapes a nested `try/catch`, so that finding uses a recorded comparison and a short source explanation. The atlas does not prove that this visual grammar improves understanding; that remains a reader study.

## Regeneration

Reading the finished page requires none of these commands. To regenerate from the supplied, built worktrees:

```sh
cd ~/projects/rich-review-v2/experiments/76-scientific-specimen-atlas
npm ci
npm run capture
npm run record
npm run build
npm run check
node scripts/verify.mjs
```

The browser checker defaults to system Google Chrome; `ATLAS_CHROME` can select another executable. Capture and recording write only inside this experiment and temporary fixture directories they create themselves. They do not rerun the focused Symnav suites.
