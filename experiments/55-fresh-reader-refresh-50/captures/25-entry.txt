01 ↗
STATED REASON
The owner moves; the mechanisms stay

Required slices of the existing DaemonPolicy replace optional numbers and local defaults. CLI composition supplies them; CLI modules still execute the mechanisms.

Omitted composition must not recreate local defaults. — PR body

02 ↗
STATED REASON
One memory derivation feeds the whole daemon

Delete the CLI’s duplicate resource-policy calculator. RSS thresholds, reports, worker heap limits, sampling, and the replacement circuit now use resources directly.

One threshold owner; shed before replacement and stop persistent churn. — spec + policy record

03 ↗
STATED REASON
Carry the capacity through every reader and writer

Capture, disk spools, worker messages, and result codecs use the output slice. JSON and execution-control frame caps come from transport. Chunk ≤ inline ≤ result ≤ aggregate remains the policy constraint.

Bound raw records, retained output, and control input centrally. — PR body + policy record

04 ↗
STATED REASON
Keep each lifetime and polling clock distinct

Startup ownership, authorization, heartbeats, idle lifetime, stop escalation, signal waits, and drain acknowledgements receive named values. Existing timer absences remain, including healthy warm-up, accepted work, and result retention.

Preserve each existing cadence and lifecycle allowance. — policy record

05 ↗
STATED REASON
Diagnostics get their own bounded slice

Log rotation, backup count, queued writes, and disconnected-trace retention use diagnostics. Trace expiry is independent of result retention.

Bound diagnostic storage and retain reconnect evidence. — policy record

06 ↗
STATED REASON
Choose the deadline by the caller’s purpose

Status observation selects 100 ms; ordinary lifecycle and execution-status use 250 ms. Admission gets 5 s, and acceptance removes the completion timer. Request names do not select the deadline.

Status aggregation and ordinary execution-status have different deadlines. — PR body

07 ↗
STATED REASON
Keep the recovery budgets nested

An accepted request gets one reattachment by default; each execute attempt gets its own fetch allowance of one. Nesting already existed; limits become numeric policy controls. Fetch failure leaves its attempt; the sketch covers defaults.

Each reattached execute attempt needs its own fetch allowance. — PR body

08 ↗
STATED REASON
Count startup child-failure retries separately

Startup’s fixed second try becomes a policy-bounded loop. Only child exit or lost warm-up spends this budget; the default is one retry. It is separate from delivery recovery.

Preserve one fresh launch after a failed child. — policy record

09 ↗
STATED REASON
The small-threshold seam lives in tests

Seven new test helpers translate old constructor knobs into validated policy values. Tests, helpers, e2e fixtures, and the benchmark switch to those adapters. Production drops the legacy threshold options.

Tests need small thresholds without restoring production tuning seams. — PR body

10 ↗
UNEXPLAINED REASON
Some old test premises disappear

The CLI resource-derivation block and literal cadence assertion are deleted; central policy tests already exist in the base. Startup tests drop timeout overrides, including the 5 ms healthy-warm-up setup.

No explicit rationale found for these individual removals in the supplied body, commits, or plans.

11 ↗
UNEXPLAINED REASON
Test adapters also reshape the inputs

Spill thresholds rise; formerly zero-inline cases write extra bytes. Helpers clamp capacities and create test output directories. Some expected limits now come from policy. A one-byte chunk case is added.

Validated test policies are stated intent; the exact replacements and clamp choices have no recorded reason.

12 ↗
UNEXPLAINED REASON
The reattachment loop changes which error escapes

If a reattached receipt is obtained but its completion later rejects, the new loop can report that later error. The old wrapper reported the original error. Receipt-acquisition failure still preserves the prior error.

The PR explains numeric budgets, but gives no reason for this error-selection change.

13 ↗
UNEXPLAINED REASON
The boundary is policed with retired names

A meta-test expands a production-source denylist of old constants, optional knobs, and duplicate policy owners. It rejects matching text; it is not a complete proof that every threshold has one owner.

Enforcing ownership is stated in the spec. No reason is given for this particular text-list approach.
