02 / THE COMPLETE STOPPING LAYER

Read the seams.
Keep the questions visible.

The window and these 14 open records form the complete layer. The details below only increase fidelity. “Unexplained” means no specific rationale was found in the supplied PR body, six commit messages or policy/spec records.

01

Make the policy input required ↘

The existing frozen snapshot supplies output, resource, transport, startup, shutdown, delivery and diagnostic limits. CLI mechanisms lose local defaults; they still live in apps/cli. Process and worker snapshot bridges already existed.

statedomitting composition must not recreate local defaults.

02

One output slice, several enforcing surfaces ↘

Capture, spool, file decoding, transfer framing and worker validation share output limits. Raw chunks remain distinct from JSON/control-frame caps; limits now travel through storage and codec signatures too.

statedStated in the PR and policy record: required output slices bound records, individual results and aggregate retained output.

03

Consume memory thresholds once derived ↘

The duplicate CLI resource-policy class and WorkspaceDaemon’s fallback derivation disappear. Resource sampling, replacement limits, worker heap limits and heap sampling consume the snapshot directly.

statedStated in the architecture spec: numeric limits belong to the daemon policy object. The policy record gives each threshold’s purpose.

04╱

One retired option still appears in tests ↘

Ready records read hardProcessRssBytes directly; the production base already passed that value through memoryCapBytes. The test helper still accepts memoryCapBytes without mapping it into policy. Benchmark resource records gain policy circuit fields.

unexplainedno specific reason found for the unused helper option or expanded benchmark record. The production input removal follows the stated centralization intent.

05

Keep each lifetime’s own purpose ↘

Startup, idle/stop/termination, drain ACK polling, logging and disconnected traces use their own slices. Stop reserve remains min(maximum, floor(stop/2)); trace capacity keeps a minimum of one. Diagnostic retention is separate from result retention.

statedStated in the policy record: preserve separate cadences and bounded diagnostic history; keep a reserve even in small stop windows.

06

Choose the timeout when composing the caller ↘

daemon status selects status-observer → 100 ms. Ordinary lifecycle and execution-status exchanges use 250 ms. The same request kind can therefore get different waits. Execute admission keeps its separate 5 s bound; acceptance removes that timer.

statedstatus observation and ordinary execution-status requests have distinct deadlines.

07

Equal allowances, different scopes ↘

The default is one accepted-execution reattachment per request and one result-fetch resume per execute attempt. Numeric policy limits replace fixed retry structure and a boolean. The base already kept the fetch allowance inside each attempt.

statedeach reattached execute attempt has its own fetch-resume allowance.

08╱

The loop has two less obvious edges ↘

A failed reattached completion can now expose its later error instead of the first accepted-close error. Also, a failed result-fetch is terminal: setting its numeric limit above one does not build a repeated-fetch loop.

unexplainedthe PR explains separate counters, but not the changed completion-error selection or this limit’s one-fetch control flow.

09╱

Required inputs still have different shapes ↘

Some consumers take a whole snapshot, some a section or Pick, and codecs take numbers. Registry grace retains a per-call override; StoredCommandOutput’s chunk argument remains optional. The worker parent re-parses serialized policy for its chunk cap.

unexplainedno common projection rule or specific explanation for these remaining seams was found. Current production composition supplies their policy values.

10

Keep tuning adapters in tests ↘

Seven new Test* helpers translate legacy numeric options into policy-backed construction. Production compatibility overloads are avoided; output capture tests now inject dependencies carrying policy.

statedtests need small thresholds without restoring runtime tuning seams.

11╱

Adapting a number changes some test stimuli ↘

Policy validation requires positive, ordered output caps. Fixtures change sizes and record splits. The transport adapter raises inline 0 to at least 64 KiB and creates the output directory, so a tiny-output cleanup check can pass without a spill.

unexplainedno specific reason found for the weaker spill stimulus or the selected fixture rewrites. Validation explains why the old zero cannot pass unchanged.

12╱

Remove local derivation tests ↘

The CLI derivation table, constrained-memory test and interval-constant test are deleted with the duplicate class. Existing package tests overlap, but their table substitutes a 1-byte boundary for the deleted 256-MiB input; CLI supervision tests remain.

unexplainedno specific reason found for the exact deleted cases or the unmatched 256-MiB row. Policy centralization explains removing the duplicate implementation.

13

Guard the retired names ↘

The meta-test broadens its production-source denylist to 36 strings. It catches those retired names, not every possible numeric bypass; the exact guard design has no stated rationale.

statedStated intent in the PR: reject retired defaults and bypasses. Unexplained: why this particular name-based guard is sufficient for that intent.

14

Count child failures; keep healthy startup unbounded ↘

A fixed second startup launch becomes a childFailureRetryLimit loop (default one; new tests use zero and two). The unused startupTimeoutMs option disappears. No healthy-startup or post-accept completion deadline is added.

statedStated in the policy record: preserve one fresh launch after child failure; progressing warm-up has no project-size deadline and accepted work is not failed merely for running long.

BEFORE

→
HEAD

Reattached completion failure → current completion error. Failed fetch still terminates.

Base catches a reattached completion failure and rethrows the original error. Head assigns the new completion then awaits it on the next loop iteration, where that failure becomes the current error.
