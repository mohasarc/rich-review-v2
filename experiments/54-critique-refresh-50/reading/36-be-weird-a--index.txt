03 / COMPLETE DECISION LAYER

The calls a human owns.

STATED a reason appears in the inputs
UNEXPLAINED no specific reason found

This is the stopping layer. It includes the API choices, exception behavior, test changes, and unanswered rationale. Magnification below adds evidence to these same decisions.

01
STATED
Move the lifetime owner

Core exports the generic scope and cache interface. TypeScript keeps semantic algorithms, key construction and project resources; its service calls into core.

Plan: language-independent retention belongs in core.

↗
02
STATED
Share expiry, isolate stores

One scope owns six typed stores: five promise caches by symbol identity and one location cache by file position. Callers reuse reference discovery; call-target resolution reuses definitions.

PR: the existing key and value spaces are independent.

↗
03
STATED
Cache “nothing” too

A present key whose value is undefined stays cached. An empty location array stays cached too. Lookup uses Map.has before Map.get.

PR: undefined is a valid cached value.

↗
04
STATED
Cut only after success

Successful backend refresh begins the next cache turn. A failed refresh leaves existing query entries available. The refresh ordering already existed before this PR.

PR: preserve the current successful turn when refresh fails.

↗
05
STATED
Clear now; finish later

Release synchronously empties all stores, then awaits project release. Backend completion now waits and receives project rejection. Queries can repopulate the cleared stores while release is pending.

PR: old entries must be unavailable while release is pending or rejecting.

↗
06
STATED
Keep the exact return

No promise wrapping or cancellation in the cache: rejected promises stay cached; synchronous factory throws retry. An old pending promise may settle after clearing without replacing a new entry.

PR: preserve promise/value identities and failure behavior.

↗
07
UNEXPLAINED
Contain the scope

The query service creates and contains a TurnScopedCacheScope. The architecture plan describes shared core bases extended by TypeScript; this cache extraction uses composition.

No specific reason for this shape was found.

↗
08
UNEXPLAINED
Expose a manual scope

Handles expose only getOrCreate. Explicit scope calls clear all stores. There is no timer, closed state or handle disposal: stores work before beginTurn and after release, and live with the scope.

The public surface is listed; this exact API shape has no recorded reason.

↗
09
UNEXPLAINED
Pass files, not the snapshot

The exported service’s beginTurn parameter narrows from WorkspaceSnapshot to readonly WorkspaceFile[]. Backend passes snapshot.files. The service continues storing the supplied files reference.

PR announces the signature change but supplies no reason for it.

↗
10
UNEXPLAINED
Reuse locations; project again

Locations cache; reference promises/results and position node arrays are fresh on access. Position nodes are looked up again and can be the same node. This existing behavior stays. Backend async wrappers are a separate boundary.

Preservation is requested; the specific reason for reprojecting locations is not given.

↗
11
STATED
Characterize before extraction

Six service tests and four core tests are added. The five existing service tests and their assertions remain. Commit order records characterization, scope specification, implementation and adoption.

Contributor guide calls for informative tests before implementation.

↗
12
UNEXPLAINED
Reconcile the release promise

The PR introduces awaited release; the larger spec promises unchanged lifecycle outcomes. A deferred/rejecting injected graph changes completion/error behavior; concrete TypeScript cleanup is synchronous here. No reconciliation is recorded.

The local ordering rationale is stated. Its fit with global parity is not.

↗

Entire six-file delta inspected. No unrelated edit or removed/weakened existing assertion found. “Unexplained” is limited to the supplied PR body, six commit messages, checked-in plan and contributor guide; no implementing conversation was supplied.

05 / HOW THIS PRINT WAS MADE

A relation, not a replay.

The probe takes eight observations from each of six caches. Every pixel asks Object.is(read A, read B). The two prints use the same procedure, each in its own build. Matching colors across prints do not mean shared memory.

Cache contents are read through TypeScript’s compiled private fields. The return lens observes the query service’s public return values: promises for D/R/T/C/E, a node array for P. The backend adds async wrappers, so this is not a promise-identity claim about the backend API.

Real TypeScript workspace state and algorithms run against target(); missing();. Only refresh failure and project release scheduling are controlled. Separate small probes use injected state to isolate rejection and release ordering. No production source is edited.
