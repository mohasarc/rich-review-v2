STATED
PLAYED

ALTERNATIVE NAMED IN PR

Choose a timeout from the request’s kind.

The same identify or ping message can serve different callers. An execution-status request still uses the ordinary timeout; the word “status” does not select 100 ms.

End the execution timer at acceptance
STATED
PLAYED

COACH’S VARIATION · HYPOTHETICAL

Carry that timer into command completion.

07
Give recovery two independent budgets
STATED
PLAYED

Count execute reattachments outside; count fetch resumes inside each execute attempt.

ALTERNATIVE NAMED IN PR

Share a single used-retry flag across both recovery scopes.

A reattached execute attempt receives a fresh fetch allowance. Reattachment resends the same request identity after an authenticated accepted close; this is recovery, not local replay.

Default: one reattachment and one fetch resume per attempt. Base already nested the two scopes; this PR replaces fixed one-shot control with policy numbers. Added trace: execute → reattach → fetch.

Reason on record: The PR says every reattached execute attempt has its own fetch-resume allowance.

Let the latest completion error escape
UNEXPLAINED
PLAYED

A later accepted completion failure is caught in the next loop iteration.

BASE BEHAVIOR

Always preserve the original accepted-close error.

When reattachment is accepted and its completion fails, the exposed error can now be that later failure. A failure before reattachment acceptance still rethrows the preceding error.

An effect of the numeric loop rewrite, separate from the stated reason for independent counters. No correctness verdict is attached.

09
Keep the fetch path as one connection
UNEXPLAINED
PLAYED

Read a numeric resume allowance at the original execute socket; fetch itself has no retry loop.

COACH’S VARIATION · HYPOTHETICAL

Retry failed fetch connections until that numeric allowance is spent.

The code distinguishes an allowance from a complete repeated-fetch mechanism. Fetch failure rejects this attempt. The new reattachment test makes one fetch; it does not demonstrate repeated fetch failures with a limit above one.

Default limit is one. The limit check lives in executeOnce.resume(); fetchCompletion().catch(fail) exits the attempt. Outer recovery still has its own eligibility checks.

Reason not found: The PR explains independent counters, but does not explain retaining one fetch connection while accepting a numeric resume limit.

COACH’S VARIATION · HYPOTHETICAL

STATED

COACH’S VARIATION · HYPOTHETICAL

STATED
