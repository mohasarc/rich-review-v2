Six stores stay separate.

04 / Lookup · D3–D4

A promise is the cached value.
The scope never waits for it.

↑ D3: values
↑ D4: failures

Key is already present

  1. Map.has(key) is true.
  2. Return Map.get(key) exactly.
  3. Do not call the factory.

Applies to an empty array, an explicit undefined, or a promise that has rejected.

Key is absent

  1. Call the factory synchronously.
  2. If it returns, insert that exact value.
  3. If it throws, insertion is never reached.

A returned promise is inserted immediately. A thrown error leaves no entry, so the next lookup retries.

Stated · D3–D4

The PR explicitly preserves value/promise identity and failure behavior. Its reason for Map.has is that undefined can itself be a cached value.

Factory behaviorSecond access in the same cache intervalAt a clearing boundary
Returns a value or empty arraySame cached value object.Entry removed. Next lookup runs the factory.
Returns undefinedCached hit; no factory rerun.Entry removed.
Returns a rejected promiseSame promise, same rejection.Entry removed; old promise is not cancelled.
Throws synchronouslyFactory runs again.No failed entry was inserted.
Old promise settles after a new turnIt can settle for its original holders. It cannot overwrite the new entry: the scope has no settlement callback that writes to the Map.

The identity promise belongs to the cached query layer. Public findReferences awaits location data and constructs reference results again. Position definitions cache locations, then return a newly built node array on each access. These projections remain in TypeScript.
