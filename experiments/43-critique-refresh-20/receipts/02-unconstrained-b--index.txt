AUTHORITY

The CLI composes a DaemonPolicy. The daemon receives serialized values and reconstructs the same snapshot; its worker receives those values too. This bridge predates this PR. The new work connects consumers to it.

OUTPUT

02
Keep the operating envelope
stated
REASON FOUND

The existing policy record gives a reason for every value and for the intentional absence of these deadlines. The architecture spec requires one policy owner and forbids user tuning.
plans/005/daemon-policy.md; architecture spec · Every threshold has one owner

OUTPUT ENVELOPE

64 KiB per chunk, 256 KiB before spilling, 256 MiB per result and 512 MiB across retained daemon spools. Control JSON and execution-transfer control use separate 8 MiB and 256 KiB limits.

RESOURCE ENVELOPE

Select a positive constraint only if smaller than total memory. Floor effective memory to MiB, then derive half for hard RSS (256–8192 MiB), one quarter for worker old generation (128–4096 MiB), and 80% / 70% of hard RSS for shedding / resumption. Raw effective bytes remain in the snapshot; no CLI production read of that field remains in this PR.

INDEPENDENT CLOCKS

The 100 ms status budget, 250 ms ordinary response budget and 5 s admission budget remain separate. Stop keeps min(500 ms, floor(stop budget / 2)) for escalation; trace capacity keeps an effective minimum of one.

INTENTIONAL ABSENCES

The record says healthy warm-up progresses without a project-size deadline, accepted work has no completion timer, and worker output acknowledgement waits without a timer. Startup-silence policy and unacknowledged-result eviction are deferred.

Let composition choose the response clock

REASON FOUND

The PR says status observation and ordinary execution-status requests have distinct deadlines.
PR body · Decisions 2

SELECTION

Only the daemon status action supplies responseTimeoutPurpose: status-observer. The constructor picks the response deadline once. Other callers get the ordinary purpose by default.

CONSEQUENCE

An identify or ping exchange gets the clock of the instance sending it. An execution-status message does not acquire the status-observer clock because of its name. The same instance-wide choice is also used for acknowledgement and endpoint probing.
