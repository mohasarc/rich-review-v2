# Which parts of 40 have a distinct job?

40’s strongest idea is to preserve relationships that otherwise get conflated: where code lives versus who owns an instance, cached objects versus returned objects, empty caches versus settled cleanup, and disclosure versus rationale. Those are reasons to retain a representation. A credit to each of thirteen earlier experiments is a construction history, not evidence that all thirteen devices belong in the default reading path.

This is an editorial removal analysis. I read 40’s handoff, opened its actual page, inspected its opening/intent/lookup sections, selected the position-definition relation and the held-success cleanup case, and retained the rendered results in [inspection-40/rendered-routes.json](inspection-40/rendered-routes.json). I did not ask separate readers to use different ablations of 40. “Keep” below means a defensible explanatory job, not demonstrated learning benefit.

## What the operated page shows

The position-definition matrices use the same eight observations on both sides. Cached location arrays can be shared within an interval while service-return arrays are fresh. The frame reached in the held-success cleanup recording shows both promises eventually fulfilled and caches refilled by intervening queries. Together these demonstrate why the identity relationship and the release boundary are distinct jobs. They do not require treating every detail view as compulsory.

There is also real translation work: the request tour uses a three-function fixture, the identity relation uses a separate one-file fixture and the release recording uses a separate two-file fixture. 40 labels those distinctions correctly. A reader must still translate between them. I cannot infer confusion merely from their existence. The protocol for a later 40 ablation should record the reader’s own cited fixture and representation at the moment an explanation changes.

One inspection attempt tried to advance the cleanup selector after it was already at its last checkpoint. Playwright timed out on a disabled Next button. That is a harness sequencing error, not evidence that 40’s control failed. [operated-routes.json](inspection-40/operated-routes.json) preserves the failed call; [rendered-routes.json](inspection-40/rendered-routes.json) preserves the successful read afterward.

## What would justify a stronger cut

Assign distinct unfamiliar readers to a default 40 path with versus without one optional device, preserve the corrected complete layer, and ask an unshown-case prediction before crossover. Retain the literal explanations and which view each reader cites. A device earns default space when it supports a distinction the remaining path did not support for that reader. Do not treat this author’s inventory as that observation.
