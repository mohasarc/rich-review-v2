# typographic-morphology

## Entry point

Open [index.html](index.html) directly; no server, installation, network, or worktree is needed:

```sh
open ~/projects/rich-review-v2/experiments/80-typographic-morphology/index.html
```

**A word learns its boundaries** follows `WorkspaceDaemon` through four extractions, its rename to `DaemonProcessCoordinator`, package staging, and physical consolidation. Play the changes, scrub eight source snapshots, or select any word to open its explanation and exact receipts. **Escape** returns focus to that word. The focused specimen also accepts Left/Right, Home, and End. Reduced motion retains every snapshot and disables playback.

The ten open readings below the specimen form the complete stopping layer. They can be read in order or entered independently; the source reader has previous/next and return controls. [The static evidence book](evidence/reading.html) works without JavaScript. The animated page and all its sources also work from `file://`.

- Opening style: a compact typographic trajectory, followed by the original compound word and its four still-embedded domain words. The spatial analogy is marked beside the timeline.
- Shape: one box’s history within a pyramid. Opening proposition → animated specimen and ten complete readings → matching mechanisms, author reasons, and exact source receipts. No factual revelation is gated behind playback.
- Navigation: chronological snapshots and a range scrubber; nonlinear word selection; a ten-reading linear source tour; direct `#step=148` and `#read=copies` addresses; browser Back; Escape/focus restoration; static evidence fallback.

## What I tried

The folder already contained a broad research pass: vocabulary/import changes, constructor options, 23 proposed readings, member lineage, and package naming ratios. I kept that material but reduced the public artifact to one ownership story and ten readings. Carrying all the vocabulary and options would have made a decorated inventory rather than a typographic explanation. The previous broad layer remains in [content/entry.mjs](content/entry.mjs); it is not bundled into the page.

The central experiment works: the same domain words move from one fused body into separately named classes. At #148 the entire family acquires a second physical impression; at #149 only the package impression survives. GSAP supplies the layout transitions and Recursive’s `CASL` axis supplies the package letterform change. These are schematic source transitions, not recorded runtime events.

The initial desktop draft had excessive vertical space and a constructor parenthesis that could imply the static projector was constructed there. I reduced the space and separated the class-public signature from the import joins. The initial phone version overflowed its four names; two columns now preserve their spelling and selected method samples. A midpoint screenshot also caught entering name parts crossing the moving `Daemon` word; the new parts now appear after that move. Early screenshots are preserved in [evidence/attempts](evidence/attempts/).

A receipt check corrected “identical bodies”: the #148 class source matches **after normalizing one inline import-type path**, while ordinary imports are also re-addressed. Exact raw files remain available. The static audit also replaced an imprecise text search for class declarations with AST confirmation, so declaration strings inside tests cannot count as additional production classes.

The empty package lane consumes substantial space in early frames, although it makes the later copy visible. The ten complete readings remain more prose than the main type instrument.

| Two complete impressions | Source implementations at CLI and package addresses | At #148 the CLI graph remains active and frozen; unit suites follow the staged package. Not two running processes. |
| Solid / dotted underline | Stated rationale / no specific rationale found | Applied to reading words; the renamed class is dotted. An unadorned reading is a source observation. |
| Order and movement | Selected source snapshots across the stack | Eight snapshots have unequal temporal gaps. Interpolation is illustrative, never runtime simulation. |

Letter size supports reading hierarchy and fit; it is **not** proportional to lines, importance, or responsibility. The letterform, package address, method weight, and explicit text together keep the representation usable without color discrimination.

## Libraries considered and used

- **Used: [GSAP Flip](https://gsap.com/docs/v3/Plugins/Flip/)**, installed version 3.15.0. It captures browser layouts before DOM reparenting and animates to the new word locations. GSAP also owns playback scheduling, cancellation, color, and CSS font-axis interpolation. No custom animation engine, FLIP implementation, camera, graph layout, or routing system was written.
- **Used: [Recursive Sans & Mono](https://www.recursive.design/)** through `@fontsource-variable/recursive` 5.3.0. Its weight, monospace, and casual axes let a word retain identity while changing appearance. The local Latin full-axis WOFF2 and OFL license are shipped in `assets/`; no font CDN is required. Native browser shaping and Flex/Grid perform the layout.
- **Considered: [Motion Canvas](https://motioncanvas.io/docs/)**. Its timeline and code-animation facilities suit a narrated film. Here, selectable source text, independent word inspection, keyboard controls, and responsive reflow favor DOM typography with GSAP. It was not installed or used.
- **Considered: [opentype.js](https://github.com/opentypejs/opentype.js)**, installed 2.0.0 by the earlier research pass. Glyph outlines and ligature access could support contour morphs. I rejected outlined text before implementation because contour interpolation would obscure exact spelling and need a second accessible text representation. It remains a development dependency, but is not imported or bundled.
- **Used for extraction/build:** TypeScript 5.9 and esbuild 0.28.2. The compiler identifies classes, imports, members, and named test declarations. esbuild produces the checked-in self-contained script.
- **Used for verification only:** Playwright with an isolated headless system Chrome. No browser dependency is needed to open the result.

## What the form teaches better or worse

**Better:** extraction is felt as a word ceasing to be crowded. A method can visibly remain light/private even after its domain word separates. Two impressions with the same class name make the #148 staging interval harder to confuse with a completed cutover. The #149 deletion removes an address rather than pretending to remove a running process. Letterform and color make the surviving package ownership perceptible.

**Worse:** typography cannot establish behavior preservation, show runtime order, or explain full collaborator APIs. The import joins carry less directional information than arrows. Identifiers with long suffixes are slow to scan; on phones they need two rows. The complete rationale/test story still needs concise prose and source receipts. No human comprehension study was performed, so these are design observations rather than demonstrated learning gains.

## Rebuild and repeat

From this experiment folder:

```sh
npm ci
npm run capture
npm run build
npm run verify
npm run check:browser
```

`capture` uses the retained, pinned research snapshots and read-only Git objects available in `~/projects/symnav`. `verify` independently rereads the source and checks `worktrees/main` and `worktrees/stack-head`. Scripts write only inside this experiment. The browser checker defaults to `/tmp/rich-review-05-browser/node_modules/playwright` and system Chrome; set `MORPHOLOGY_PLAYWRIGHT` and `MORPHOLOGY_CHROME` for other installed locations.

For a full research refresh, the earlier `scripts/extract.mjs`, `scripts/build-data.mjs`, and `scripts/test-bodies.mjs` regenerate their corresponding research files before `capture`. They inspect local remote-tracking refs and check the tip pin. The broad `content/entry.mjs` and exploratory probe scripts are retained as an unfinished earlier approach; they do not supply the published ten-reading content.

The received brief is [brief.md](brief.md). No Symnav source or branch was modified, committed, pushed, or rebased. Queue, index, and campaign completion handling are left to the orchestrator.
