# Design and scope

The lesson is the separation of accepted-work identity, transfer progress, and completion ownership in PR 148. This is a deliberately narrow review; unrelated routing guards, election, worker lifecycle, clock changes and their test changes are outside its explanation.

Read, in order: campaign philosophy; playbook (including required sections 1, 2, 3, 6, 7); READMEs 04, 23, 36, 37, 53. Additional README survey: 15, 64, 66, 67, 68, 69, 70. READMEs 72–74 were not yet present at survey time. No earlier implementation or evidence was reused.

Borrowed standards: 04 actual-method recordings with bounded claims; 23 complete opening and local receipts; 36 separate identity from value; 37 direct navigation and focus return; 53 keyboard parity and explicit physical-analogy limits. To avoid repeating 15's moving envelopes or 66's transit map, this chamber accumulates record particles, makes partial framing physically hold at a membrane, and decays only the object whose source lifetime ends.

Library evaluation: PixiJS 8 ParticleContainer fits hundreds of byte marks and retained record trails; Graphics and Text supply inspectable boundaries. GSAP timelines supply deterministic playback, pause and seek, plus MotionPathPlugin for recovery arcs. Matter.js was considered for collisions, but rigid-body impulses would imply physical scheduling; rejection and deduplication are protocol predicates, so their visual responses follow recorded events. Three.js and regl offer GPU rendering but add camera/depth or shader work with no explanatory gain here. No force physics, graph layout, semantic zoom, custom tween loop, generated bitmap assets or network runtime dependencies.

Official documentation examined: https://pixijs.com/8.x/guides/components/scene-objects/particle-container, https://gsap.com/docs/v3/GSAP/Timeline/, https://brm.io/matter-js/docs/classes/Collision.html. Exact versions are locked locally.

No ambient particles: each mark represents a byte, an output record, a control message, a request identity, or a diagnostic trace. Speeds, paths, sizes and rebounds are illustrative. A rebound is a visual rejection, never a claim that the protocol sends the particle back. Fading chalk is trace expiry, not spool eviction.

The top layer must mention: staging/frozen active CLI; length/binary/validation framing; manifest/record ordinal/append barrier/digests; bounded fetch versus identical-execute reattachment and conflict; no local replay after accepted or ambiguous closure; finish→ack→caller and failure cleanup; trace expiry versus spool/ledger retention and deferred eviction; scoped relocated-test evidence. Every lower view refines these only.
