01 / BoxDiagram

Use boxes for real units, boundary rectangles for ownership, and named directional edges for interaction. Coordinates belong to the author: the kit does not guess an architecture. Changed and removed strokes are distinct in both color and pattern. Every linked box remains an ordinary keyboard-accessible SVG link.

BoxDiagram(
  id="owners", title="Who clears?", description="…",
  width=530, height=378,
  boxes=(Box("scope", 230, 317, 248, 34,
             "TurnScopedCacheScope", tone="changed",
             target="scope-detail"), ...),
  edges=(Edge("service", "scope", "clear", tone="changed"),),
  lossy_note="Simplified: relevant classes only."
).render()

See the paired ownership diagram in PR 127. On narrow screens the SVG scrolls inside its figure to preserve legible labels. The text description gives the relationship to assistive technology. A static picture cannot explain lifecycle alone; pair it with the same choices shown as a sequence.

02 / BeforeAfter

Two panels, always present, with a shared frame of reference. Supply diagrams, tables, timelines, or code as the contents. Label both versions and put any simplifying assumption beside the comparison. The component stacks the panels on narrow screens without swapping their order.

BeforeAfter(
  id="release", title="When release finishes",
  before=before_sequence, after=after_sequence,
  before_label="Base", after_label="Head",
  note="Illustrative sequence; not a runtime recording."
).render()

See release before and after, and a public signature before and after. The component is the same; the representation matches the subject.

03 / DecisionCard

A choice is mandatory. A reason is either stated, with an evidence destination, or unexplained, with a description of the search boundary. The card does not infer intent from the code and has no verdict or response fields.

06
REASON STATED
Clear immediately; make release wait

Keep synchronous clearing before project release. Now the service and backend await project release, so its pending state and rejection reach the caller. The stack spec also asks for unchanged failure paths.

The PR says released semantics must be unavailable while release is pending or rejecting. It requests the awaited barrier; reconciliation with the stack's parity wording is unexplained.

See how it works ↗
Reason source ↗
DecisionCard(
  id="decision-id", number="01", title="The choice",
  choice="What this change commits to, including its limits.",
  status="stated",
  reason="The reason the source actually gives.",
  target="mechanism-id", reason_target="evidence-id"
).render()

For an unexplained choice, set status="unexplained" and omit reason_target. A changed signature is not automatically a reason for that change. Reason provenance is separate from evidence that the implementation exists.

04 / ExitLink

An exit is a normal anchor with a stable origin ID. JavaScript adds the return address to a destination’s direct header, opens enclosing native details, and moves keyboard focus after navigation. Browser Back, copied links, modifier-clicks, direct file opening, and JavaScript-disabled reading retain standard browser behavior.

ExitLink("origin-id", "destination-id", "Follow release").render()

The invariant lives in authoring, too.

Give every root decision an ID. Declare each lower section’s parent and claim IDs. validate_layers rejects missing parents, duplicate IDs, and a child claiming a decision its parent never announced. It cannot detect a novel fact hidden in prose: read each descent manually. PR 127’s coverage manifest makes that audit reviewable.

Default to a visible overview followed by mechanisms, then evidence. Link any high-level box or card to its lower section. The page remains one linear document, and every destination has a fallback way back.

What this kit leaves to the author

Choice extraction, honest rationale attribution, ranking, drawing coordinates, and matching a representation to the subject. The kit supplies structure; a reusable component cannot supply understanding on its own.
