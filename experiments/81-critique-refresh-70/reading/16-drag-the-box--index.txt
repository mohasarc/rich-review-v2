02 / THE COMPLETE DECISION MAP
What the PR chooses
Read these cards and stop, or follow a source.

These choices cover the changed policy consumers, deadline and retry scopes, test migration, deleted tests, changed fixtures, and unexplained details. The lower layers add the exact wiring and evidence.

01
stated
Require policy at composition

Omitting a consumer’s numeric options can no longer recreate local defaults. Seven existing policy sections feed the CLI mechanisms; their implementation files and package rules stay in place.

Mechanism & evidence ↗
02
stated
Carry one set of output capacities

Capture, completion spooling, transfer framing, and both sides of worker chunk validation consume the policy’s limits. Required capacity arguments replace imports of spool-owned constants; stored-file decoding carries the same bound.

Mechanism & evidence ↗
03
stated
Stop deriving a second resource policy

The CLI resource-policy class disappears. The supervisor, process RSS reports, V8 worker limit, sampling timers, and replacement circuit use the snapshot’s resource values directly.

Mechanism & evidence ↗
04
stated
Give each lifecycle limit its own input

Startup ownership, heartbeat and polling; stop, idle, signal exit and drain acknowledgements; log rotation, write queues and disconnected traces all read their policy sections. Healthy startup and accepted completion still have no deadline.

Mechanism & evidence ↗
05
stated
Choose a timeout by the caller’s purpose

Status aggregation gets 100 ms; ordinary lifecycle and execution-status exchanges get 250 ms. Execute admission gets 5 s. The composing caller chooses status-observer, rather than inferring it from the request kind.

Mechanism & evidence ↗
06
stated
Keep recovery counters in separate scopes

Startup child failures use a numeric retry allowance. Accepted execution has a reattachment counter; each execute attempt gets its own fetch-resume counter. Defaults remain one of each.

Mechanism & evidence ↗
07
stated
Keep compatibility in seven test helpers

Test adapters translate legacy knobs into validated policy snapshots. Production constructors require policy; tests can still request small limits. Some tests import an adapter under the original runtime class name.

Mechanism & evidence ↗
08
unexplained
Retire tests with the local policy class

The CLI’s five-row memory-derivation table, constrained-memory assertions, and 250 ms constant assertion are deleted. Central policy tests already exist; the supervisor’s cadence test stays. No separate deletion rationale was found.

Mechanism & evidence ↗
09
unexplained
Change the shape of small-output tests

Replay’s spill threshold goes 1 → 32 bytes; zero-inline spool cases use positive limits and extra writes. Helpers clamp or translate legacy limits, create an output directory, and retain an unused memoryCapBytes option. These exact choices are not separately explained.

Mechanism & evidence ↗
10
unexplained
Let the later attempt’s error escape

The old one-reattachment path rethrows the first completion error if the reattachment fails. The numeric loop can instead surface a later completion’s error; a failed reattachment submission still rethrows the preceding completion error.

Mechanism & evidence ↗
11
unexplained
Guard retirement with source-text tokens

The meta-test expands its production-source denylist to retired constant names, class names, and optional knobs. Preventing policy bypass is stated; choosing this specific name-based guard is unexplained.
