New lifetime implementation / handle boundary
Manual clearing moves out of TypeScript

A turn is a cache lifetime. It starts after a successful backend refresh. Release clears entries immediately, but does not cancel returned promises or block new queries. The new wait belongs to the TypeScript release chain.

THE DECISIONS / COMPLETE AT THIS LEVEL

What a reader needs to weigh

Reasons come from the PR and spec. Two API choices have no located rationale. The release barrier also meets a stricter parity promise in the stack spec.

01
REASON STATED
Put cache lifetime in core

Export TurnScopedCacheScope and its typed handle from core. TypeScript still chooses when to begin a turn and release; core clears the entries.

The architecture spec assigns shared cache lifecycle to core and semantic query bodies to the language backend.

REASON STATED
Keep six independent caches

One scope owns six separate typed handles: definitions, references, call targets, callers, callees, and position definitions. Each keeps its own Map.

The PR explicitly chooses isolated handles over a shared map because the queries have independent key and value spaces.

Return the exact cached value

REASON STATED
Keep two different failure paths

A returned promise stays cached even after rejection. A factory that throws before returning stores nothing, so the next lookup retries it.

The PR's context commits to preserving existing failure behavior. New tests characterize asynchronous query failures and synchronous reference failures.
