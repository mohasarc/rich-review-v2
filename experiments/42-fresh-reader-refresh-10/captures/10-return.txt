THE WHOLE CHANGE, BEFORE THE DETAIL
Eight decisions on this route

Each door adds mechanism and source evidence.
Stated = a reason was found. Unexplained = no reason was found.

01
STATED
↗
Core owns lifetime; TypeScript owns meaning.
One scope per semantic service, with six isolated caches. The service still holds the scope instance. Algorithms, prepared source state and project logic stay where they were.
The spec assigns language-independent cache lifetime to core; the PR keeps six handles because their key and value spaces are independent.
02
STATED
↗
Keep each answer’s identity and key space.
Five caches hold promises by symbol identity; one holds locations by file + position. Hits preserve exact values and empty arrays. The generic core API also caches undefined. Reference projections and node arrays are rebuilt.
The PR explicitly preserves the existing algorithms, keys and identities. Map.has is chosen because undefined is a valid cached value.
03
STATED
↗
Only a successful refresh starts a turn.
Both versions clear after refresh succeeds, including an unchanged snapshot. A failed refresh leaves the current semantic cache entries available. This is a cache guarantee, not rollback of every refresh side effect.
The PR says failed refresh must preserve the current successful turn.
04
STATED
↗
Clear immediately. Then wait for project release.
Both versions clear first. The new service returns Promise<void> and the backend awaits it: pending release stays pending; an asynchronous project rejection reaches the backend caller.
The PR says released cache entries must be unavailable while release is pending or rejecting. It names the backend as the awaited release barrier.
05
STATED
↗
Keep rejected promises; retry a factory that throws.
A returned promise is cached even if it rejects. A synchronous throw occurs before insertion and can be retried. Clearing neither cancels an old promise nor lets its later settlement overwrite a new entry.
The PR explicitly preserves query failure behavior and promise identity; the added tests characterize both kinds of failure and old-promise settlement.
06
UNEXPLAINED
↗
Expose small, reusable handles.
Core exports the scope and getOrCreate interface. Handles survive repeated clears; there is no public per-key invalidation, disposal, unregister, or lifecycle gate. The service keeps six for its lifetime.
No specific reason for this exact public API or handle-registration lifetime was found in the PR, commits or supplied spec.
07
UNEXPLAINED
↗
Pass files instead of the whole snapshot.
The exported semantic service changes beginTurn(snapshot) to beginTurn(files: readonly WorkspaceFile[]). The backend passes snapshot.files; other snapshot fields no longer cross this method boundary.
The PR lists the signature change, but gives no reason for choosing this narrower input.
08
STATED
↗
Add evidence around identity and lifecycle.
Six semantic-service cases and four core cases are added. The five existing service cases and their assertions remain. No deleted or weakened existing assertions were found in this six-file diff.
The commits explicitly characterize semantic identities, specify the core lifecycle, and specify awaited semantic release.
Two statements to hold together

The architecture spec asks for unchanged behavior. This PR explicitly adds an awaited release barrier, changing when release completes and where asynchronous release errors arrive. Read both sources ↗
