THE COMPLETE READING / SEVEN BOUNDARY READINGS

What the skyline is telling you.

This city teaches physical ownership and change surface. These seven open notes name every decision and exception explored below; it is not a complete review of every mechanism in the stack.

01

Reusable work moves to core#123–128

Source caching, revision publication, project membership, semantic-cache lifetime and workspace sessions gain a core home. TypeScript keeps language-specific work; CLI keeps hosting.

Stated: other backends and future hosts need the reusable mechanisms without importing TypeScript or CLI.

Read this boundary more closely

The same green concern can leave a purple TypeScript district or a coral CLI district and appear inside core. A moved source-cache file is a change of home; revision, graph and session extraction also change the surrounding files. Height counts the edited text, so it cannot tell a pure move from a redesigned API.

02

A new address starts with contracts#129–134

CLI takes state-directory resolution from telemetry. Daemon becomes a leaf package for policy, command/failure vocabulary and admission authority; CLI mechanisms consume those contracts.

Stated: CLI composes environment values; the daemon needs an enforceable owner with no internal production dependencies.

Read this boundary more closely

At #130 the daemon district exists before its process mechanisms move there. #131 wires consumers to required policy slices; #132–134 give vocabulary and admission decisions a single authority. A contract-patterned building is still a source file: the pattern is a path-based grouping, not a claim that its contents contain only types.

03

The host plugs in; formatting moves out#135–136

An injected executor module keeps CLI execution behind a daemon-owned contract. Lifecycle report formatting moves into renderer; format selection and writing stay in CLI.

Stated: the daemon must stay free of CLI/core imports, while renderer owns the output bytes.

Read this boundary more closely

The executor module URL is a host-supplied seam, not an import from the daemon package back into CLI. The renderer relocation is another crossing: the formatting building changes district without moving output selection and writes with it. The cyan road marks a selected source relocation, not a network socket or elapsed trip.

04

Smaller owners can share the old district#137–147

Codec, transfer receiver, socket clients/server, activity projector, worker generations, delivery and accepted execution get separate owners while their mechanisms still live in CLI.

Stated: isolate framing, connection, recovery and lifecycle responsibilities before the package move.

Read this boundary more closely

New blue buildings inside CLI are evidence of decomposition without physical package separation. The white invocation road still enters the CLI dispatcher and local transport. The intervening eleven skylines change the internal surface; they do not show a package cutover.

05

Two blue neighborhoods, one active path#148

DaemonClient and package mechanisms arrive. The public façade loads its private runtime dynamically. The active CLI graph remains in place: 38 compatibility files are frozen while the package is staged.

Stated: separate mechanism ownership from the host-invocation switch, and keep Node-backed mechanisms out of host declarations.

Read this boundary more closely

Both districts contain daemon concerns at this skyline. The white road stays inside CLI, whose dispatcher still constructs its local registry, transport and startup coordinator. The new package has a real implementation, but its presence alone does not establish the shipped CLI route. The source inventory hashes the 38 files; the city independently recomputes that digest.

06

The road crosses; the old block clears#149

CLI invocation now reaches DaemonClient. The 38 frozen files disappear; blue test buildings remain in CLI. Daemon owns mechanisms, entry points and transport composition; external tests use a read-only inspector, with compiler-based ownership checks.

Stated: make the package the sole mechanism owner, while CLI retains argv/workspace coordination and tests receive observation without storage authority.

Read this boundary more closely

The road starts at CLI entry, passes through CliInvocationCoordinator and crosses into the daemon façade. Empty outlined lots are removed physical paths, not proof that their behavior disappeared. The old compatibility directory is required to be absent, and the daemon package exports explicit entry/testing surfaces rather than compatibility aliases.

07

Lit windows are not a coverage claim#148 · test relocation

37 CLI test files move into daemon source. A worker test switches to a generic fixture and drops startup/result timing checks. Its CLI-version mismatch case leaves the worker test; a host executor test checks version rejection instead.

Stated: package independence motivates generic executors; a commit explicitly restores the host version oracle. Unexplained: no specific reason found for removing the timing observations.

Read this boundary more closely

The checker pattern identifies test paths, not assertions or passing tests. Rename detection links old test parcels to new homes. In the selected worker patch, fileCount and output checks remain while duration fields leave. Commit 0f31a619 adds direct CLI executor version-rejection coverage, which does not reproduce the original worker initialization-failure observation. No claim is made about timing coverage in other suites. No symnav test suite or production daemon was run for this city.
