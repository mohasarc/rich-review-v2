# policy-reading-loom

## Entry point

Open [index.html](index.html) directly, offline:

```sh
open ~/projects/rich-review-v2/experiments/74-policy-reading-loom/index.html
```

No installation, server or live worktree is needed to read it. Select a consumer–slice crossing, then choose **Surface / Wiring / Receipts**. Depth stays fixed when either coordinate changes. **One field 64 KiB**, **Same value 250 ms**, and **Two allowances 1 + 1** pull different sets of strands. The exact-field selector exposes every drawn leaf.

On a focused crossing, arrow keys move through the grid; Page Up/Down changes depth. **Previous / Next** follows the fifteen active crossings. **Return to surface** keeps the crossing. **Locate crossing** restores grid focus. Browser Back restores the address; receipt dialogs close with Escape and return focus. All twelve open readings and the [source book](evidence.html) work without JavaScript. Narrow screens scroll the matrix inside its own viewport and provide ordinary coordinate selectors.

## Declared choices

- Role framing: a learner comparing policy identity with consumer purpose. Narrow question: **does sharing a field mean sharing a job, and does sharing a number mean sharing a field?**
- Box lenses: static package/module ownership and composition/input authority. Policy lives in `@symnav/daemon`; the named consumer families remain in `apps/cli`. The earlier parent-side worker parse is an explicit runtime failure-boundary exception.
- Opening style: a marked loom analogy and before/after authority strip. Intuition comes from pulling one leaf through several consumers, then pulling equal numbers that do not connect.
- Shape: complete stopping layer = opening + fabric/legend + twelve open readings. The optional inspector repeats the same subjects as wiring and source receipts. Eight readings have stated reasons; four retain specific rationale gaps. A stated general migration reason does not fill a specific implementation gap.
- Navigation: address `(consumer family, policy slice, depth)` plus an independent highlighted thread set. Seven rows × seven columns remain fixed at every depth. Even empty coordinates can be selected. Linear active-crossing traversal, reading-to-crossing jumps, exact returns, URL fragments and history supplement the grid.
- Trust posture: pinned source, conservative reasons, bounded actual-method observations and explicit changes to test premises. No correctness judgment, verdict buttons, comments, review storage or collected responses.
- Persona: a TypeScript-familiar teammate who has not followed daemon policy composition.
- Representations used: orthogonal matrix; individual field strands; shared/unique knots; reading/forwarding ties; rationale rims; three thread comparisons; byte-proportional recorded output bars; open marginal readings; exact line-numbered source dialogs.
- Importance rule: distinguish field identity, purpose and enforcement first. Recovery errors, parent validation, adapter behavior and deleted/changed tests remain on the open surface even when they make no attractive strand.
- Inputs used (beyond bundle): pinned head/base implementations and changed test source, unchanged policy implementation and tests, `plans/005/daemon-policy.md`, architecture specification, Git blobs/status, and a fresh probe of actual capture/codec/worker-validator methods. Bundle used: `pr.json` including all six commits, `diff.patch`, `files.txt`, and relevant `repo-rules.md` clauses. Overview dumps and other subjects were not used. No implementing conversation was supplied.
- Tech: D3 7.9.0, HTML/CSS/SVG, esbuild 0.25.10, Python source capture, Node method probe, Playwright 1.61.1 and system Chrome. System fonts; local assets and bundled runtime dependencies. Codex; no subagents.
- Built on earlier experiment(s): **37-be-weird-b** supplied the independent-addressing principle, extended here from decision × depth to family × slice with depth held separately. The required READMEs for **04-textbook-chapter, 23-zoom-canvas, 36-be-weird-a, 37-be-weird-b and 53-be-weird-53** informed pinned receipts, bounded recordings, complete stopping layers and focus returns. No earlier implementation, evidence bank or probe was copied. A README representation-field survey across existing experiments, plus closer reads of **62-policy-stained-glass** and **67-blast-radius-terrain**, avoided glass regions, ranked readership, terrain and shared-file overlap as the explanation. Representation metadata for **61, 65, 66, 68 and 69** was also inspected. The distinction here is a fixed individual-leaf matrix with three independent reading coordinates; it does not count references or project overlaps into geography.

## What I tried

Compared spreadsheet grids, Plot cells and D3 before implementation. A cell containing one aggregate symbol would hide whether two families read the same leaf, so the final fabric draws every one of the 38 traced leaves as its own vertical strand. Fifteen family–slice crossings contain 53 knots. Light ties distinguish forwarding from reading. Empty grid positions remain navigable to preserve the coordinate algebra.

The first browser render exposed a missing favicon; it was fixed. Source reconciliation added the base production entry for the already-hard-RSS reporting claim and the benchmark return shape for the adapter claim. Full-width screenshots made it clear that the whole grid needs its own reading viewport below the large opening. On phones, the grid remains horizontally scrollable while the inspector uses normal text and selectors. Draft captures are retained under [evidence/attempts](evidence/attempts/). No complete representation was abandoned.

The real-method probe uses source files bundled from each pinned worktree, avoiding dependence on pre-existing `dist/` freshness. The head fixture sets chunk/inline/result/aggregate to 4/8/12/24 bytes. Capture produces 4 + 4 + 2 byte records; base produces one 10-byte record. Both decode to the same text. A five-byte codec or worker message passes the base limit and is rejected under the head fixture's four-byte ceiling. These observations teach policy propagation; they are not an end-to-end parity result.

## What I would drop

The oversized opening title and tiny secondary module labels. The open readings are lengthy, but the representation cannot honestly encode error provenance or adapter precedence without words. The inner inspector scrollbar also costs discoverability; the full source book and open readings provide a simpler reading path.

## What I would do next

Ask a fresh reader to distinguish the chunk strand from the three 250 ms strands, then compare two consumers while holding Receipts fixed. Compare their explanation with one produced from an ordinary dependency diagram. No human comprehension trial was run.

## Visual-variable legend

| Variable | Encoded fact | Limit |
| --- | --- | --- |
| Row | Curated consumer family | Multiple named classes can be grouped; these are not processes or reference counts. |
| Column | Actual `DaemonPolicyValues` slice | Seven slices remain fixed at every reading depth. |
| Vertical strand | One exact policy leaf | Crossing an unrelated row without a knot does not connect that row. Strand length is not measured reach or runtime traffic. |
| Color | Capacity ochre; time teal; memory violet; recovery rust | Purpose categories are an authored reading aid, not types in the repository. Values carry units in the inspector. |
| Circle / diamond knot | Leaf appears in several drawn families / only one drawn family | A diamond does not imply only one method or call site in the repository. |
| Heavy / light tie | Family reads a required value / forwards a slice to another shown family | Required refers to the input contract; it does not mean every constructor validates policy at runtime. |
| Solid / dashed cell rim, `U` | Stated adoption reason / specific rationale gap on the open surface | A dashed rim does not mean unvalidated, incorrect or more severe. General reasons can coexist with specific gaps. |
| Highlight | Selected exact leaf, equal-value set, or two delivery fields | Highlight changes inspection only. It does not edit policy or simulate execution. |
| Depth control | Surface, wiring or exact receipts at the same coordinate | No semantic zoom; matrix position and geometry do not change. |
| Recorded bar width | Bytes per output record in the saved probe | Injected tiny policy fixture; no daemon, socket or performance measurement. |

The source map intentionally omits `resources.effectiveMemoryBytes` as a direct consumer leaf: it belongs to central derivation. The map also omits transitive references and composition sites outside the named family inventory. Its 38 leaves are an authored route model, not a compiler census. See [field-map.md](evidence/field-map.md).

## Libraries considered and used

| Option | Evaluation |
| --- | --- |
| [D3 band scales](https://d3js.org/d3-scale/band), [data joins](https://d3js.org/d3-selection/joining), symbol shapes | **Used.** Nested band scales place slices, families and leaves. D3 joins render stable crossings and thread selection. SVG makes one strand continuous across cell boundaries. No custom graph layout, diagram router or camera engine was needed. |
| [AG Grid cell components](https://www.ag-grid.com/javascript-data-grid/component-cell-renderer/) | Considered. Its grid interactions are attractive, but a continuous leaf crossing several rendered cells would still need a separate overlay. Spreadsheet editing, sorting and virtualization do not help this fixed 7 × 7 comparison. |
| [Handsontable cell renderers](https://handsontable.com/docs/javascript-data-grid/cell-renderer/) | Considered. Appropriate for cell-oriented data manipulation; this read-only artifact needs continuous strands and a depth coordinate outside the grid. |
| [Observable Plot cell mark](https://observablehq.github.io/plot/marks/cell) | Considered. A strong compact matrix alternative. Multiple leaf knots, mixed forwarding weights and independent coordinate focus fit direct D3 selection more naturally here. |

Runtime dependencies are bundled locally with [third-party notices](THIRD-PARTY-NOTICES.txt). No hosted fonts, APIs or network requests are required to read the artifact.

## What the form teaches better or worse

The same vertical line can enforce different jobs without splitting into unrelated arrows: capture, spool, codec and worker all use the chunk leaf. Conversely, three aligned-looking 250 ms values remain physically separate strands in different slices. Circle/diamond shape and heavy/light ties let a reader separate sharing from forwarding. Keeping depth fixed makes comparison a change of address rather than a fresh descent through a hierarchy.

A conventional diagram would label each relationship more directly and scale better when only a few relationships matter. The loom's geometry uses space for empty crossings and its smallest labels need the inspector. It does not explain recovery error provenance, test deletion or normalization through cloth alone; those receive open readings and paired receipts. These are design judgments, not measured learning outcomes.
