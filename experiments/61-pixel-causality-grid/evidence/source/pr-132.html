   3 Command labels had four runtime owners, and daemon process code inferred operational identity by scanning opaque argv. A command-looking option value or target could therefore override the command selected by CLI syntax.

  94 ## Decisions
  95 
  96 - Chose a frozen daemon-owned tuple over another app-local set, because runtime validation and the union must change together.
  97 - Chose an exhaustive CLI record over deriving workspace routes from the full tuple, because help, version, control, and unknown are syntax routes rather than workspace commands.
  98 - Chose `commandName` beside opaque argv over nesting or reparsing it, because argv normalization and operational labeling have different owners.
  99 - Chose to include `commandName` in accepted-request compatibility over comparing argv alone, because retry attachment must preserve original operational identity.
 100 - Chose a new protocol generation over optional or legacy command metadata, because either mixed-generation direction must take established compatibility handling before execution.
