# command-me-reader

## Entry point

Open [index.html](index.html) directly:

```sh
open ~/projects/rich-review-v2/experiments/69-command-me-reader/index.html
```

**Keep holding it** is a seven-part ritual: point → drag → predict → hold → release → compare → say it back. Its narrow lesson is that clearing a lookup does not cancel a caller-held promise, and old settlement does not replace a new entry.

No installation, server, network, or live worktree is needed. Every gesture has a button equivalent. Space/Enter can hold the old reference; there is no required holding duration. Every stage can be opened directly, replaying its setup. Source links open exact receipts and return focus to the originating link. The complete eight-reading surface and [source book](sources.html) also work without JavaScript.

## Declared choices

- Role framing: learner acquiring and holding a reference. Each command has a consequence: point locates the association; drag acquires another reference; predict separates lookup from settlement; hold crosses the clear; release settles injected old work; compare checks which identity is still in the lookup; teach-back articulates the boundary.
- Box lenses: runtime reference ownership/lifetime, with a static TypeScript service → core class ownership comparison. The service owns its scope instance; core supplies its implementation. The cache handle and caller area stay fixed while their references diverge.
- Opening style: a marked gesture analogy and the complete narrow claim, with its source immediately available. The answer is not locked behind the ritual.
- Shape: opening + instrument/legend + ownership comparison + eight open readings form the complete stopping layer. The ritual adds enacted mechanism; 23 exact receipts and raw recordings supply evidence. The heading alone is not a complete PR explanation.
- Navigation: seven directed stages with independent jumps, a conventional open register, local source dialogs with exact focus returns, and a linear static source book.
- Trust posture: source-grounded explanation; stated reasons are distinguished from specific rationale gaps. The separate awaited-release change and its reconciliation gap remain visible. No verdict, score, comments, or answer collection.
- Persona: a teammate who knows TypeScript but has not worked in this cache implementation.
- Representations used: duplicated reference tokens, physical hold/release, persistent handle geometry, lookup-arrow replacement, pending/fulfilled texture, identity color and subscript, paired result readout, private prediction and teach-back, package ownership strip, open decision register, exact source receipts.
- Importance rule: the difference between losing a lookup and losing a reference first; then preserved identities, lifecycle ordering, caller-visible completion, API choices, rationale gaps, and test changes.
- Inputs used (beyond bundle): read-only source and freshly built modules from the two supplied worktrees; contributor guide; architecture and follow-up specifications; a plan-directory search for cache-lifecycle rationale; actual-method recordings using injected factories/state; a focused head test run; isolated browser checks. Bundle inputs: PR body and six commit records, full patch, file counts, relevant repo-rules material. Precomputed overviews and other subject bundles were not used.
- Tech: XState 5.20.2; GSAP 3.13.0 with Draggable; HTML/CSS and system fonts; esbuild 0.25.5 for a local IIFE bundle; Python source capture/rendering; Node recordings; Playwright 1.55.0 with system Chrome; axe-core 4.10.3 for automated accessibility checks. Codex harness, no subagents.
- Built on earlier experiment(s): no implementation, data, evidence, or content reused. Read the five assigned READMEs: 04-textbook-chapter for controlled-run honesty, 23-zoom-canvas for complete outlines/returns, 36-be-weird-a for identity at a named observation surface, 37-be-weird-b for independent access to depth, and 53-be-weird-53 for physical-analogy limits. Also surveyed representation fields in 15, 17, 24, 26, 40, and 54–68. Avoided the existing identity matrix, loom, spring/recoil bench, musical score, and timeline. [Design notes](design-notes.md) record the distinction.

## What I tried

Considered a wiping/eraser sweep and a pressure threshold. Dropped both before implementation: Map.clear is synchronous, and there is no pressure or time threshold in the source. Chose a press that advances the boundary immediately; the reader can keep holding to inspect it. Letting go advances the injected completion. Single-step buttons reproduce the same states.

The first browser pass found a title overflow at 320 px. Responsive type sizing fixed it. Source review also caught an index excerpt that missed the actual export and a base-release excerpt missing its signature; both now include the exact lines. Pointer, touch, keyboard, cancellation, direct-stage setup, source returns and reduced-motion checks pass. No representation was abandoned after implementation.

## What I would drop

The five miniature extra handles are secondary to the one-handle lesson. The full PR register is useful for coverage but dominates reading time on a phone. This is the cost of keeping every decision visible around a narrow exercise.

## What I would do next

Observe unfamiliar readers explaining why old settlement cannot replace the new entry, once with the ritual and once with the same static diagram. Check whether holding teaches the boundary or merely makes it memorable.

## Visual-variable legend

| Channel | Fact it carries |
| --- | --- |
| Rust + P₀ / blue + P₁ | Old versus new promise identity. Identity is local to each recorded run, not shared across builds. |
| Dashed circle / filled circle | Pending versus fulfilled promise. Text labels repeat the state. |
| Left lookup / right caller | Two holders of references; a dragged token is another reference to the same object. |
| Persistent H rectangle | The same reusable handle remains after its entry clears. |
| Arrow from key to circle | The key’s current lookup association; it changes from P₀ to P₁. |
| Press / physical release | Advance clear + new lookup / advance injected old settlement. No elapsed time, pressure or computation rate is measured. |

The page labels the gesture analogy beside the instrument. It compresses a key, isolates one of six handles, and uses generic injected values “old” and “new.” The caller enclosure is not a memory address or garbage-collection model. The finger’s release is not `releaseTransientResources()`.

## Libraries considered and used

[XState](https://stately.ai/docs/transitions) was selected for explicit legal transitions and direct-stage reconstruction. [GSAP Draggable](https://gsap.com/docs/v3/Plugins/Draggable/) was selected for mouse/touch dragging, hit testing and short return/state motion in the same library. Reduced motion removes the brief fades and return animation; the state changes still occur. These are pinned versions, not a claim about the latest release.

[Interact.js dropzones](https://interactjs.io/docs/dropzone/) were a viable alternative but would leave motion as another choice. Native drag/drop needed additional touch handling; React gesture packages added an unnecessary framework. There is no general graph to lay out or route. Audio was rejected because it would not carry an additional fact. GSAP's license pointer/README and XState's MIT license are preserved under [vendor](vendor/); bundle legal notices are retained.

## What the weird form teaches

Better than the static diagram, the ritual makes the reader maintain one reference while a different holder loses it. The unchanged physical location of P₀ and the unchanged shape of H distinguish promise identity, lookup ownership and handle lifetime simultaneously. Releasing old work while blue P₁ stays in the cache also makes “old settlement cannot overwrite the new entry” visible.

Worse than a conventional diagram, the hand can suggest that a caller controls work completion. The inline analogy label and button equivalents make that limitation explicit, but cannot erase it. The narrow scene does not explain all six query algorithms or daemon behavior. Reading the separate awaited-cleanup change still needs the compact register and source chain. These are design judgments, not measured comprehension gains.

## Regeneration

Opening needs none of these commands. To rebuild from the supplied pinned worktrees, run inside this folder:

```sh
npm ci
npm run capture
npm run build
npm run check
python3 scripts/verify.py
```

`capture` verifies the pins, reads source, and imports existing build output. Rebuild the worktrees first if their compiled modules are missing. The focused test log is retained as a recorded run; `build` does not silently rerun Symnav tests. Browser checks use an installed Chrome. Capture, recording and page-building scripts write only inside this experiment. The received [brief](brief.md) is retained; queue, index and commit handling belong to the orchestrator.
