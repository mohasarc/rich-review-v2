## Declared choices

- Role framing: A reader recording decisions before consulting independent source, then a source checker correcting that account.
- Box lenses: Whatever each page declares; verification emphasizes code ownership, process boundaries, lifetime, failure timing and test-observation boundaries.
- Opening style: A marked simplified reading sequence, with the three descent findings named immediately.
- Shape: One complete comparison table; separate source and parent/child receipts.
- Navigation: Linear table, local filters/search, original-page links, captured text, evidence anchors and return links. No stored reader input.
- Trust posture: Sealed blind notes, pinned revisions, finite witnesses, explicit inference and recall corrections. No correctness scores or approval controls.
- Persona: One technically literate serial reader. Later pages benefit from vocabulary learned earlier; this is not a controlled trial with independent fresh humans.
- Representations used: Rendered page text and screenshots, a comparison table, exact parent/child quotations, line-numbered source excerpts and JSON records.
- Importance rule: Changes to caller outcomes, failure boundaries, ownership authority and what a test actually observes receive attention alongside the advertised architecture. An omitted source fact alone does not establish a witnessed rule-4 descent.
- Inputs used (beyond bundle): Philosophy and required playbook sections; README entry/kind/subject sections; rendered finished pages; the supplied #127/#131/#148 bundles; read-only Git objects for immediate revisions, #146/#147 and focused stack context; applicable worktree AGENTS files; the narrated page’s transcript. No external web sources.
- Tech: Offline HTML/CSS/JavaScript generated with Python. A private Playwright/Chromium process captured pages; existing local browser tooling was reused. Reading the report requires none of it.
- Built on earlier experiment(s): Read 01–37 and 40 as critique subjects. Read 39 only after the blind seal and principal independent source checks. Its protocol-source, policy-retirement and executor-default observations prompted credited verification. Did not read critiques 38/41 or reuse another experiment’s report code. No v1 material was accessed.

## What I would drop

Treating “all PR-body decisions” as a complete change inventory. The pre-spawn validation boundary and altered disk stimulus show why that is insufficient.

Treating every extra number or line of code as a rule-4 surprise. The report requires a concrete parent/child change in the account. I also dropped a proposed miss in page 06 after re-reading K3: serial test scheduling was already there; my notes had omitted it.

The first browser selector attempts in page 35 targeted hidden close buttons. I kept the failed captures, corrected the selectors and opened the intended records. Those are harness failures, not page failures. Large tool-output reads also required smaller contextual follow-ups; this did not become evidence of exhaustive reading.

## What I would do next

Have independent readers visit one page each and predict concrete outcomes before seeing source: pending cleanup, failed reattachment, an exactly-at-threshold record and overlapping configured projects. Compare predictions with the same pinned witnesses. This would separate page teaching from transfer between earlier readings.
