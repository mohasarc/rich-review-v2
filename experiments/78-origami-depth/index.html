S Stated reason U Reason not found

Ownership & API

Core supplies the clearing class; each TypeScript service holds one scope and six isolated handles. S: generic lifetime in core; independent key/value spaces. Composition, the exact exported getOrCreate/scope API, and its private clear-only handle shape have U: no specific reason found. The package dependency already existed.

Values & failures

Algorithms and keys stay in TypeScript. Hits preserve stored identity, including rejected promises; undefined is cached with Map.has. A synchronous factory throw leaves no entry, so the next lookup retries. References share stored locations; reference results and position nodes are reprojected. S: preserve contracts; allow undefined. U: original projection design.

Entries ≠ handles

Both lifecycle calls clear every store synchronously; handles remain usable, even after repeated release. Clearing removes cache lookup access to old values. It does not cancel caller-held promises, and old settlement cannot replace a new entry. S: one-turn lifetime and preserved promise behavior. No disposal or cancellation API is added.

Successful refresh

A turn begins only after refresh succeeds, as before. A failed refresh keeps the current successful turn’s cached results. S: preserve the last successful turn. The service now receives readonly WorkspaceFile[] instead of the whole snapshot. U: why narrow that exported signature here.

Cleared ≠ finished

Both revisions clear before project cleanup. S: old semantics must be unavailable while cleanup is pending or rejecting. Head adds a service promise and two awaits: backend completion now waits and carries cleanup rejection. U: reconciliation with the spec’s unchanged-behavior requirement. A delayed cleanup here is injected; concrete TS project cleanup is synchronous.

Evidence & limits

Five existing service cases and their helpers remain identical; six service and four core cases are added. S: repository guidance requires tests for behavior. U: why exactly this test selection. Focused runs pass 5 base / 15 head tests. Controlled recordings cover the pictured boundaries; no full daemon or end-to-end parity is claimed.
