## What I tried

Considered a folding decision tree, but it would repeat disclosure navigation rather than explain lifetimes. Considered a physical origami mesh, but geometric constraints would not add source fidelity. Built a single strip with three owner regions and a perpendicular set of lifecycle flaps.

The first hinge direction hid the flaps behind their backing paper. Reversing the direction fixed visibility; shorter entry leaves kept the handle labels exposed. A GSAP overwrite conflict initially left the ownership wings bent in later presets; property-level overwrite fixed it. Opening now retains the empty old-lookup markers, so increasing reading depth cannot imply cache repopulation. Negative screenshots and notes remain in [attempts](attempts/README.md).

The final rationale audit distinguished the repo's general requirement for behavior tests from commit subjects naming test intent. It also kept “the PR names the await boundary” separate from “its reconciliation with parity is unexplained.”

## What I would drop

The small printing on bent faces is useful mainly on desktop. On a phone the sheet carries shape and ownership while the adjacent readout and complete edge rows carry readable detail. The decorative paper mark in the opening can go. Flip smooths the lower mechanism's changing height, but GSAP's hinge animation does most of the explanatory work.

## What I would do next

Give a reader only the sheet, legend and six edges, then ask whether an old promise can still settle and whether empty caches imply completed release. Compare their explanation with the same content shown as an ordinary sequence diagram. No human comprehension trial was performed here.

| Raised entry layer | Old lookup has been detached | Does not cancel, destroy, or garbage-collect a caller-held value |

| Gold P₀ / green P₁ slips | Caller-held old promise settles; the new cache entry remains new | Actual head core recording with deferred settlement, not a daemon workload |
| Six slots D/R/T/I/O/L | Definitions, reference locations, call target, callers, callees, position locations | First five store promises; L stores locations. Drawn contents are illustrative |
| Open-sheet microprint | Additional implementation fidelity on the same facts | Reading depth does not advance cleanup or refill a cache |

The construction is **semantic origami**, not a mechanically realizable folding pattern. Its angles and expanded writing area are layout choices. The analogy limitation appears beside the instrument, and each controlled mechanism records its own scope.

## Libraries considered and used

| Option | Evaluation / choice |
| --- | --- |
| **GSAP 3.13.0 + Flip — used** | GSAP drives all hinge rotations, source-plane depth and paper extension. Flip handles the lower mechanism's layout-height transition. Property-specific interruption lets quick changes settle to the requested shape. Vendored distribution files preserve their original headers. [Official Flip documentation](https://gsap.com/docs/v3/Plugins/Flip/) and [license notice](vendor/NOTICE.md). |
| **Motion / Framer Motion — considered** | Its independent transform animation and React layout support fit this task, but React would add a runtime solely for a small persistent paper object. [Official animation docs](https://motion.dev/docs/animate), [React layout docs](https://motion.dev/docs/react-layout-animations). |
| **Three.js CSS3DRenderer — considered** | It can position HTML in a 3D scene, but this object needs a fixed perspective rather than a camera/render loop. Its documented zoom limitations also add an unnecessary constraint to a reading artifact. Native CSS 3D retains selectable source text and ordinary DOM controls. [Official renderer docs](https://threejs.org/docs/pages/CSS3DRenderer.html). |

There is no custom animation clock, graph layout, diagram router, or semantic zoom engine. Geometry is an authored three-panel paper net; GSAP interpolates its transforms. Native range inputs, dialog, scrolling and focus behavior provide the interaction primitives.

## What the weird form teaches better or worse

**Better:** a handle and its contents cease to look like the same thing. The sleeve survives while its entry leaf moves away. The perpendicular cleanup fold makes it possible to see “old lookup gone” and “caller still waiting” at once. Switching source revision changes the lifetime owner's paper and the return coupling while keeping the six lanes in place. Opening for evidence preserves those identities.

**Worse:** a conventional sequence diagram states the two awaits more directly and wastes less area. Perspective makes labels harder to read, especially on a phone. Paper cannot carry rationale or test-selection gaps reliably, so the six open prose edges remain necessary. It is not an improvement for a reader who only wants exact API signatures.

## Reproduction

Opening the artifact requires none of these steps. To refresh evidence with the supplied worktrees still at their pinned commits and built, run inside this folder:

```sh
python3 scripts/capture.py
node scripts/record.mjs
```

To repeat browser checks with Node, system Chrome and the pinned development dependencies:

```sh
npm ci
npm run serve
```

In a second terminal in the same folder:

```sh
npm run check
```

`ORIGAMI_URL` can select a different local server address. The capture/record scripts write only this experiment. They do not rerun Symnav's tests. The received [brief](brief.md), original harness/log files, implementation, negative drafts, local runtime files and validation scripts are retained.
