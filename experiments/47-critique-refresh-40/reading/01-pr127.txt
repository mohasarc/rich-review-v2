02 / carry all the decisions
The complete #127 decision surface

Four authored choices, six additional contracts or choices. The rest of this page adds fidelity to these same IDs.

One scope, six isolated handles
stated

Chose one scope with six handles over one shared map, because the existing queries have independent key and value spaces.

d127-1 · #127 · reason & evidence ↗
Cache undefined with Map.has
stated

Chose Map.has before Map.get over truthiness checks, because undefined is a valid cached value.

d127-2 · #127 · reason & evidence ↗
Clear before project release
stated

Chose synchronous cache clearing before project release over clearing after the await, because released semantics must be unavailable while release is pending or rejecting.

d127-3 · #127 · reason & evidence ↗
Start a turn after successful refresh
stated

Chose to begin the next turn only after refresh succeeds over clearing at refresh entry, because failed refresh must preserve the current successful turn.

d127-4 · #127 · reason & evidence ↗
Return exact values; retain async failure; retry sync throws
stated

Each handle stores the factory result unchanged. Rejected promises stay cached for the turn; a synchronous throw inserts nothing and the next access retries. Old promise settlement cannot replace a new-turn entry.

p-identity · #127 · reason & evidence ↗
Cache positions, rehydrate nodes on each lookup
stated

The sixth cache uses relative-path:source-offset keys and stores location arrays, including empty arrays. Returned node arrays are rebuilt per access. Identity caches use formatted symbol identities; callers and refs share reference discovery.

p-position · #127 · reason & evidence ↗
The backend now observes project-cleanup completion and failure
unexplained

Both versions clear caches before project cleanup settles. Base backend release fulfills while cleanup is pending; head backend release stays pending and propagates rejection. This is an observable async boundary change within a preservation-framed PR.

p-release · #127 · reason & evidence ↗
Narrow beginTurn from a snapshot to its file array
unexplained

TypeScriptSemanticQueryService.beginTurn now takes readonly WorkspaceFile[]; the backend passes snapshot.files. The service continues to hold those files after release.

p-files · #127 · reason & evidence ↗
Clear entries; keep reusable handles and existing callers
unexplained

beginTurn and release both clear every registered map synchronously. Handles remain registered; there is no disposal or eviction API. Clearing does not cancel pending work or revoke objects already returned, and a later lookup may refill the cache during release.

p-handles · #127 · reason & evidence ↗
Add ten characterization/lifecycle tests; keep prior assertions
stated

#127 adds six semantic-service cases and four core-scope cases. Existing semantic assertions remain; one existing release call gains await. This experiment ran both affected suites: 15 tests passed.
