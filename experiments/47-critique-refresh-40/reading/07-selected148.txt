RETAIN IN CORE · #123–128
#123
Move bytes, keep replacement behavior.
Source caching moves from TypeScript to core. A selected snapshot still evicts omitted cached bytes; selection-aware retention is deferred. The PR also rewrites the repository PR template without a recorded bundling reason.
↗
#124
Prepare a candidate; publish only after validation.
Core takes revision diffs and portable indexes. TypeScript keeps its mutation journal and exact source handles. Missing-file preparation still commits one file at a time.
↗
#126
Make project membership one publication.
Core discovers, observes, validates, and publishes project membership. TypeScript keeps tsconfig and toolchain hooks; FIFO order, inferred fallback, and release order remain explicit choices.
↗
#127
Keep six caches. Give them one lifetime.
Core owns clearing, while TypeScript keeps query algorithms, keys, and identities. Clear after successful refresh and synchronously before awaiting release; cached undefined still counts as a hit.
↗
#128
Warm means keeping the same core object.
Core sessions own discovery and backend lifetime. Cold runs use request discovery, warm runs retain a catalog, selections discover afresh, each turn gets a router, and release can be repeated.
↗
NAME THE BOUNDARIES · #129–136
#129
Resolve the environment once, in the host.
State-directory resolution moves from telemetry to CLI. One canonical path feeds both consumers, including paths with missing tails. Fixture synchronization and larger status-test budgets also land here.
↗
#130
Create the package before moving its mechanisms.
A dependency-free daemon package owns portable contracts and an immutable, complete policy snapshot. Limits, memory recipes, test overrides, and intentional missing deadlines get a policy record. Mechanisms still live in CLI.
↗
#131
The snapshot becomes the only threshold input.
Consumers require policy slices. Status has 100 ms while ordinary lifecycle exchanges have 250 ms. Fetch resumes and accepted reattachments use separate counters; test adapters replace production override seams.
↗
#132
Classify argv once. Carry the name.
CLI syntax selects one daemon-owned command identity beside opaque argv. It participates in duplicate compatibility. Protocol generation changes from 4 to 5, with mixed generations taking compatibility handling before execution.
↗
#133
One outer failure vocabulary; a separate worker domain.
Daemon owns outer failure codes, validation, and precedence. CLI supplies instanceof facts; worker failures keep their distinct wire values. Accepted terminal failures keep controlled results without local replay.
↗
#134
The first failed guard owns the answer.
Authentication, readiness, pressure, draining, and duplicate compatibility are ordered. Authentication failure disconnects; retry safety comes from the rejection code, and conflicting duplicates do not mutate accepted state.
↗
#135
The worker loads its host through a module URL.
CLI implements a daemon-defined executor contract. A validated absolute URL crosses process and worker boundaries. Worker code owns sequencing, rechunking, and sampling; diagnostics remain opaque. Two test budgets become 15 s.
↗
#136
Move output bytes to the renderer.
One stateless renderer formats public daemon start/status/stop reports. CLI still chooses format, writes output, and wraps errors. Renderer imports the daemon public reports.
↗
SPLIT THE TRANSPORT · #137–143
#137
Cut framing out of the transport facade.
Operation-shaped ports replace broad concrete dependencies. Codec and validator own binary framing, integrity, and frame-kind limits; facade mapping preserves transport error meaning.
↗
#138
A connection can end before a transfer does.
One receiver retains manifest, digest, and durable offsets across reconnections. Capture owns stored output; offsets advance only after append. Decoders are fresh per socket and output disposal transfers to the caller. A test budget grows 20→60 s.
↗
#139
Give every outbound exchange one byte connection.
A socket client owns connection timeout, pull-driven reads, FIFO writes, backpressure, and closure. The facade still interprets protocol and delivery state; inbound serving waits for its own step.
↗
#140
Group bounded responses by their shared lifecycle.
Lifecycle, execution-status, and result acknowledgement use one client for correlation, deadlines, and cleanup. Acknowledgement stays off the general lifecycle port; semantic validation precedes accepted classification.
↗
#141
Split the other side of the socket.
A server owns endpoint probes, listening, per-connection response/write chains, and shutdown. It reuses the socket client for probes; concurrent shutdown callers share settlement and force can escalate a drain.
↗
#142
Recover delivery without replaying accepted work.
A dedicated execution client owns admission through acknowledgement. Fetch resumes reuse an attempt’s receiver; identical-request reattachments create a new capture. Numeric budgets remain independent and exhausted fetches retain accepted-corruption meaning.
↗
#143
Leave the transport facade with only wiring.
One required policy composes the split owners. Direct component injection preserves returned identity; the canFrame probe disappears. A source-boundary test replaces any temptation to use file length as an architecture rule.
↗
SPLIT THE PROCESS · #144–147
#144
Capture state here; project it there.
A pure activity projector consumes explicit process, clock, queue, resource, and worker snapshots. It uses the in-progress worker generation and sampled spool bytes, keeps legacy fileCount behavior, and returns frozen values.
↗
#145
One manager owns each generation handoff.
Worker startup, execution, replacement, fencing, release, and shutdown move behind a manager. Resource policy stays behind a recovery port. Warm-up sampling gates readiness; replacement is shared, while force can interrupt graceful close.
↗
#146
Coordinate delivery without taking its data.
One delivery session coordinates attachment, transfer, acknowledgement, and traces. Ledger and spool keep state and bytes. The latest delivery is the queue barrier; expired traces are fenced, and cleanup failure does not withhold protocol acknowledgement.
↗
#147
Serialize accepted turns over existing owners.
An execution session coordinates the FIFO queue, delivery, worker, resources, and lifetime. Immutable metadata stays on ledger entries; sampling gates the next turn. Duplicates attach without a second acceptance or lifetime reset.
↗
STAGE, THEN SWITCH · #148–149
#148

#149
Switch the caller. Delete the compatibility graph.
CLI invocation coordination calls DaemonClient and package transport composition replaces the old facade. External tests use a read-only inspector and package actors; syntax-aware rules enforce imports, clocks, exports, and storage. Policy serialization becomes private. Ten CLI status/stop scenarios disappear, pressure assertions change, and inspector failure handling is added.
