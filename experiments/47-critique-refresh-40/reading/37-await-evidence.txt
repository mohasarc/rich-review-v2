EVIDENCE

Move completion to the far side of project release

Backend release now waits for project release and propagates its rejection; previously it could resolve while project release was pending. The PR names this API change while also claiming failure behavior is preserved. It gives no reason reconciling those two claims.

UNEXPLAINEDAn awaited backend barrier is documented, but no rationale was found for this caller-observable timing/rejection change within a preservation-only refactor.
