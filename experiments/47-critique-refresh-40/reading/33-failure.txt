ONE WAY IN

“Released.”
Cleanup is still pending.

Suppose project cleanup takes time. In the base, TypeScript clears six caches, starts cleanup, and lets the backend’s release call finish while cleanup is pending. The caller has no completion or failure signal from that cleanup through this call.

The queries keep their algorithms
Six caches keep different kinds of answers apart.
The scope clears all six caches
Previously stored answers stop being available immediately.
The backend waits for cleanup
Only then does the release call finish or report failure.

Core supplies the scope; each TypeScript query service owns one. The backend waits for project cleanup. A fresh query turn starts only after refresh succeeds.

Illustrative failure: the new test supplies delayed, rejecting cleanup. This is not a reported production incident.

STATED · D3–D4

The PR explicitly preserves value/promise identity and failure behavior. Its reason for Map.has is that undefined can itself be a cached value.

FACTORY BEHAVIOR	SECOND ACCESS IN THE SAME CACHE INTERVAL	AT A CLEARING BOUNDARY
Returns a value or empty array	Same cached value object.	Entry removed. Next lookup runs the factory.
Returns undefined	Cached hit; no factory rerun.	Entry removed.
Returns a rejected promise	Same promise, same rejection.	Entry removed; old promise is not cancelled.
Throws synchronously	Factory runs again.	No failed entry was inserted.
Old promise settles after a new turn	It can settle for its original holders. It cannot overwrite the new entry: the scope has no settlement callback that writes to the Map.
