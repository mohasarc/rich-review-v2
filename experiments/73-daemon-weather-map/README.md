# daemon-weather-map

## Entry point

Open [index.html](index.html) directly:

```sh
open ~/projects/rich-review-v2/experiments/73-daemon-weather-map/index.html
```

No installation, server, network connection, or worktree is needed to read the built page. **Main / #149** changes the ownership weather. **Failure pressure** selects four illustrative conditions. Select an **H**, the package front, or forecast haze to inspect its decision. **Trace this weather** follows the selected failure condition. **Previous / Next** traverses all six readings; Escape closes source, then the reading, and restores focus. Reading fragments and browser Back work. **+ / − / Fit**, dragging, and pinching magnify the chart. Motion can be paused and respects reduced-motion preferences.

Desktop is the best surface for comparing the complete field. On a phone the fitted map is an overview; magnify and pan to read its labels. The complete bulletin, unrolled mechanisms, and standalone source receipts also work without JavaScript.

## Declared choices

- Role framing: learner reading a synoptic weather chart. Assigned angle: architecture as changing weather, with exact named mappings and explicit limits.
- Box lenses: static source/package ownership and runtime request/result flow. Four selected client roles cross the package front while their process boundary stays fixed. Shared files may have other callers; the process placement depicts this selected path.
- Opening style: picture and a marked weather analogy, under “The connection breaks. The request stays.”
- Shape: complete chart, legend, and six open bulletin readings → selected mechanism → pinned source. The headline alone is not the complete layer.
- Navigation: weather stations and conditions provide nonlinear entry; the six numbered readings, Previous/Next, and unrolled source book provide a linear route. Dialogs preserve the reader’s place.
- Trust posture: distinguish source observations, stated preservation reasons, an unexplained exact calibration, illustrative scenarios, and executed tests. No correctness verdict or review collection.
- Persona: a TypeScript-familiar teammate who knows Symnav but not its daemon recovery path.
- Representations used: two contour fields, selected-role pressure counts, a moving package front, a fixed process divider, animated request/result vectors, condition-dependent precipitation, forecast hatching, retained/fresh/disposed state labels, a complete bulletin, and local source receipts.
- Importance rule: distinguish a delivery attempt from accepted execution first; then ownership, durable receipt, recovery exhaustion, policy scope and rationale, and test evidence. No risk score.
- Inputs used (beyond bundle): read-only main/tip source, policy record, architecture specification, Git blobs/status, and focused existing test execution. Bundle used: `inputs/stack/pr.json` including PR bodies and commit messages; a direct before/tip diff of the scoped transport test file was generated. No implementing conversation or production trace was supplied. Precomputed overviews were not used.
- Tech: D3 7.9.0; esbuild 0.25.10 for a local classic-script bundle; Python source capture and verification; Playwright 1.61.1 with system Google Chrome. Native HTML dialogs, system fonts, and SVG. Codex; no subagents.
- Built on earlier experiment(s): **04-textbook-chapter**, **23-zoom-canvas**, **36-be-weird-a**, **37-be-weird-b**, and **53-be-weird-53** informed evidence honesty, complete-layer coverage, and return navigation. **67-blast-radius-terrain** was read to avoid repeating its elevated policy-reader terrain: this chart instead compares source concentration and recovery conditions on a flat moving field. **61-pixel-causality-grid**, **63-daemon-constellation**, and other finished README representation fields informed the novelty survey. No predecessor implementation, measurements, decision register, or source bank was copied. The [survey](evidence/novelty-survey.json) covers 70 finished READMEs and found no weather/forecast representation.

## What I tried

I considered a broader transport concentration count, including framing. That would blur existing standalone codecs and make the “pressure” denominator hard to defend. The final census names only four roles: socket I/O, accepted recovery, transfer continuity, and output capture. Three share one source file on main; the fourth has a separate CLI file. Each has a separate package file at the tip.

I evaluated D3, deck.gl and MapLibre before choosing a planar SVG chart. No full representation was abandoned. The first screenshots exposed a before-state label collision and tiny fitted phone labels. I moved the collision and added D3 optical zoom. Receiver/capture labels now change with the condition, so persistence is visible on the field. The exhausted-fetch result wind stops at its terminal marker.

The initial browser check raced the asynchronous media-preference event. A second run exposed that zero-duration D3 transitions still deferred the front update. The check now waits for the actual preference, and reduced-motion snapshot changes assign the final geometry immediately. Draft screenshots and failed check records remain under [evidence/attempts](evidence/attempts/).

## What I would drop

The outermost contour bands add atmosphere but carry less than the H count and named owner. The full source files are useful for auditing but bulky for normal reading. Optical zoom rescues phone labels while losing the simultaneous overview.

## What I would do next

Ask an unfamiliar reader to predict what survives a fetch versus a reattachment, then ask whether the moving front implies a process move. Compare those explanations with ones elicited by a conventional sequence diagram. No human comprehension trial was run here.

## What the weird form teaches better or worse

The intended advantage is seeing **three independent things at once**: responsibility concentration changes, source ownership crosses a front, and the process boundary remains fixed. Changing the failure condition leaves the same ownership field in place while receiver/capture state changes. That distinguishes “a connection ended” from “the accepted request needs to execute again.”

A conventional sequence diagram would show the precise conditional order and two nested counters more directly. The weather field gives arbitrary spatial geometry too much apparent authority unless the legend stays nearby. It also cannot carry the exact authenticated-close predicate or explain why a numeric default was chosen; those need the bulletin and source. These are design judgments, not measured comprehension gains.

## Regeneration

Opening the built page requires none of these commands. With the supplied worktrees present at the recorded pins, run from this folder:

```sh
npm ci
npm run capture
npm run build
python3 scripts/verify.py
npm run check
```

Browser checks use system Google Chrome; `WEATHER_CHROME` can select another executable. The capture/build scripts do not rerun Symnav tests. To repeat the recorded test scope, run `pnpm exec vitest run src/daemon/local-daemon-transport-execution.test.ts --reporter=verbose` from `worktrees/main/apps/cli`, and `pnpm exec vitest run src/transport/execution-client.test.ts src/transport/result-transfer-receiver.test.ts src/transport/daemon-transport-execution.test.ts --reporter=verbose` from `worktrees/stack-head/packages/daemon`.
