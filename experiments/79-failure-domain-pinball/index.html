THE COMPLETE STOPPING LAYER

Seven rules of this table.

The machine and these open rules name every decision explored here. Scope: one already-selected warm request, from submission to completion. Startup, cache turns and worker replacement mechanics stay outside this experiment.

  1. 01

    The mechanism moves; the process boundary stays.

    Main keeps these paths in CLI modules. At the stack tip, the CLI calls DaemonClient; the package owns client recovery and daemon-side admission, execution and delivery. The host still supplies the executor. Package ownership spans caller and daemon processes.

    Stated · #149 Keep host invocation choices outside daemon mechanisms. Stated · #133/#134/#142 Preserve these failure and recovery behaviors while moving their authority.

  2. 02

    Admission hits the first failing bumper.

    Authentication → readiness → resources → queue → compatibility. An authentication mismatch disconnects without a rejection frame or resource sample. Authenticated sampling is not awaited. not-ready, resource-pressure and draining permit local fallback; conflicting duplicate incompatible does not mutate accepted work or permit fallback.

    Stated · #134 Explicit order makes first failure testable; side-effect-free compatibility protects accepted state. The historical reason for this exact order is unexplained in the inspected prose.

  3. 03

    A wire promise cannot open the local gate.

    The rejection code determines retrySafe; a contradictory boolean is corrupt. Local execution is permitted only when not submitted, or after an authenticated, retry-safe rejection. A submitted but unconfirmed disconnect remains uncertain. Accepted work and terminal failures never fall back locally. Admission has a 5 s deadline; acceptance removes it, and accepted completion has no deadline.

    Stated · #134 Contradictory frames must be corrupt, not replayable. Stated · #133 Preserve controlled terminal results without replay. Stated · policy record Bound admission without failing accepted work for running long.

  4. 04

    Reattach the identity; keep the original execution.

    An accepted closed connection can reattach only to the same authenticated instance, with the identical execute request. A new attempt gets a fresh capture. The server’s duplicate branch returns original acceptance metadata without another execution. Exhaustion, or failure to reattach, returns the first accepted-close error.

    Stated · #142/#147 One client owns accepted recovery; daemon-lifetime identity makes duplicate attachment idempotent. Fresh capture belongs to a new delivery attempt.

  5. 05

    With a manifest, fetch the remaining records.

    Result-fetch resumes at the next record offset with the same capture and manifest. The illustrated break follows record 0; fetch requests offset 1. End metadata and digest must agree, then acknowledgement precedes exposure. Exhausted truncated fetch becomes accepted corrupt. A failed acknowledgement disposes output.

    Stated · #142 + policy record Fetch and reattachment have independent numeric budgets because they recover different things. Each defaults to 1. Their purposes are recorded; choosing exactly one rather than another bound is unexplained.

  6. 06

    Worker words and request words are separate.

    Inner worker vocabulary: initialization · execution · protocol · resource. Outer terminal vocabulary: controlled-resource · response-capacity · worker-exit · stopping · internal. Concrete error identity supplies facts; there is no one-to-one word translation.

    Outer precedence: resource interruption → capacity → worker exit (except an explicit stopping shutdown) → recorded shutdown code → started shutdown → internal. A worker exit during a controlled-resource shutdown is still worker-exit unless the request was marked resource-interrupted.

    Stated · #133 Separate domains, synchronize types with validation, and make precedence testable without constructing a daemon. Preserve subtype behavior without error-name spoofing. The original precedence rationale is unexplained.

  7. 07

    The observations have a boundary too.

    The readouts use 18 recorded runs of the real compiled execution client, plus admission and classifier calls. Socket peers, failures and output records are injected; server duplicate behavior and the local lane are source projections. The scoped existing suites ran 95 tests. They do not establish full-stack parity, production timing or a correctness verdict.

    Stated · #133/#134/#142 Pin vocabulary, guard order and accepted recovery. The direct authority suites were added in those PRs; no assertions were removed from those three suites at the #148/#149 move. This is a bounded test inventory, not an audit of every stack test.
