## What I tried

I narrowed a broad policy-family grammar to three consumer input signatures. A whole section is visibly larger than the set of fields consumed: 9/6, 8/2 and 6/1. The registry’s separate dashed scalar keeps the required-constructor/optional-method distinction visible in the same glyph.

I considered encoding read count as proportional intersection area, then dropped it before implementation. Binary overlap expresses the relationship; leaf points carry the count without implying fractional memory sharing. SVG.js supplied clipping and animation, so no scene or animation engine was written locally.

Screenshot and browser passes corrected unequal column widths/source alignment, a 320-pixel class-name overflow, and a separated scalar label crossing a shifted square. The receipt audit corrected several initially truncated excerpts and now checks that each section excerpt contains every counted field. [Composition notes](spikes/library-decision.md) and a [pre-fix browser failure](evidence/browser-check-failure.json) preserve the negative observations. No complete alternative representation failed or was abandoned.

## What I would drop

The separation control contributes less than field selection: moving the parts temporarily suspends the very alignment/overlap rules being taught. It remains explicitly illustrative. Source-row labels could become quieter once a reader has learned the grammar.

## What I would do next

Give the three glyphs to an unfamiliar reader and ask which fields a constructor requires, which it reads, and whether the registry can still use a numeric grace argument. Compare their explanations with the same source contracts in a conventional diagram; no human comprehension trial was performed here.

## Visual-variable legend

| Variable | Architectural meaning | Exact boundary of the encoding |
| --- | --- | --- |
| Circle | A value surface: a policy section, old record, grouped constants or a scalar input | Record members count once; repeated glyphs do not imply multiple runtime policy objects. |
| Square | The real production consumer | Fixed size. Its center remains in CLI production before and after. |
| Triangle | Test call-site composition of the real consumer | A fixture or test adapter, not a test result. The resource override factory itself remains in the package testing entry. |
| Hue + letter | R/red = resources; S/blue = shutdown; E/yellow = startup | Color never encodes correctness. Text labels preserve the distinctions without hue. |
| Circle rim | Solid = required input; dashed = defaultable input; absent = local constant | Required is a TypeScript contract, not proof of runtime validation. Square/triangle outlines have no optionality meaning. |
| Circle area | Number of exposed fields; a scalar counts as one | Radius = `30 × sqrt(fieldCount)` in glyph coordinates. Circle sizes share a common scale across equal-width columns. Other shapes stay fixed. |
| Overlap | The square uses values; test code constructs the real consumer | Binary relationship only. Intersection area does not encode count, memory identity, call order or duration. |
| Alignment | Shape centers register to daemon package policy, CLI production or CLI test call-site rows | The source ownership move is the circle’s change of row; the square does not move. Alignment is explicitly suspended during separation. |
| Field ink | White points in the circle/square overlap are directly read fields; open points are received but unread by this consumer | Distinct field names, not access frequency. Exact counts verified against source. Scalar labels carry their single value without additional points. |

The compact version is open on the page. The grammar applies to the three selected consumers; it is not an executable formal model of all daemon code.

This was a capability evaluation, not a library benchmark. [Notes](spikes/library-decision.md) preserve the choices.

## What the weird form taught

**Better:** one compound simultaneously carries policy family, field exposure, actual readership, constructor requirement, source home and test composition. The extra dashed registry circle changes the meaning of an otherwise matching form. The before/head change can move the value source while holding the production consumer’s row fixed. A conventional dependency edge alone does not express those differences.

**Worse:** the reader must learn the grammar, the 9-versus-8 area difference is subtle, and overlap can initially suggest a Venn diagram or memory sharing. The page labels that limit. Exact field names, method arguments, rationale and test attrition need short textual readings and receipts. The phone layout preserves individual glyphs but loses simultaneous comparison across three source-aligned columns. These are design observations, not measured learning outcomes.

- [Source bank](evidence/sources.json): 18 frozen documents, 30 exact excerpts, revisions and SHA-256 hashes. Both the package policy and its tests are byte-identical between the pinned base and head. [Source book](evidence/source-book.html) opens every full file with line anchors.
- [Capture checks](evidence/capture-checks.json): section sizes 9/8/6 and distinct direct reads 6/2/1 extracted and reconciled to source. Counts apply only to these three classes; no PR-wide census is claimed.
- [Actual-method recordings](evidence/recordings.json): default/custom cadence arguments captured from real supervisor `start`; real terminator constructor fields inspected; real registry grace method invoked with synthetic owner/time; actual policy factories exercised on zero cadence and equal thresholds. Timers were intercepted. No process was signalled, registry file read, full daemon launched or wall-clock guarantee measured. The page displays saved results rather than simulating arbitrary inputs.
- Both worktrees completed `pnpm build`. [Focused run receipt](evidence/test-runs.json): **16 base resource tests, 10 head resource tests and 25 head package policy tests passed**. Raw output is alongside the receipt. These are the supplied tests, not new implementation-mirroring tests, and do not establish full command or daemon parity.
- [Browser checks](evidence/browser-checks.json): 13 groups passed, covering direct `file://` opening, before/head, animated/reduced-motion separation, all 23 fields, all six descent/return paths, 31 source buttons and focus returns, keyboard, touch, fragments/Back, 320/390/768/1440-pixel layouts, SVG label bounds, print and JavaScript-disabled source reading. No page errors or external requests in the final pass. Desktop and mobile [screenshots](screenshots/01-opening.png) were visually inspected.
- [Pyramid audit](evidence/pyramid-audit.md): explicit mapping of all authored depth to the six visible readings, plus the rationale search boundary. [Static check receipt](evidence/static-checks.json) covers hashes, excerpts, local links, contract files and clean tracked worktrees; it does not purport to automate understanding.

Only this experiment and allowed build output were written. Symnav source and branches, other experiments, the index and the queue were left untouched. No commit, publication, review response or persistent user state was created. The received [brief](brief.md) is preserved.
