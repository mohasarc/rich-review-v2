# forensic-light-table

## Entry point

Open [index.html](index.html) directly:

```sh
open ~/projects/rich-review-v2/experiments/77-forensic-light-table/index.html
```

No installation, server, network connection or live worktree is needed to read it. JavaScript must be enabled. The renderer and frozen evidence are local.

Choose a spectral film, change its exposure, then drag its colored edge across the plate. The range below the plate provides the same operation by keyboard. **Register all films** restores alignment. Four guided exposures introduce the repeated production bodies, active CLI graph, moved tests and rationale gaps. Select a band or use **Locate a file**; **Inspect source** opens its exact comparison. The nine open readings below the plate are the complete stopping layer, with matching source receipts and return controls.

## What I tried

Initially considered a full-file bitmap under OpenSeadragon and a two-image before/after wipe. Both emphasized visual registration while hiding the crucial third position: the CLI copy that remains at head. I chose three measured source stations and seven independently composited evidence films. The geometry is a measurement plot, so it needs no graph layout or semantic zoom.

An early similarity probe stripped imports with a regular expression. The final capture uses TypeScript AST import ranges and exact retained lines. It deliberately leaves inline import types, re-exports and indentation in the comparison: 28 counterparts match, while ten retain differences. Those ten are not labeled ten behavior changes.

The first screenshot left selected-file evidence below the viewport. I added an in-plate reading and source button. A browser check then caught mismatched moved-test IDs, which had selected a fallback comparison. The IDs were corrected and all 80 selections checked. Visual inspection caught mobile film controls clipped by their grid; they now use two columns on small phones, and the check explicitly measures their bounds. Two overly broad source ranges were corrected. Initial screenshot and failed-check receipts remain under [evidence/iterations](evidence/iterations).

No full representation was abandoned after implementation. The negative design choices are recorded here rather than presented as functioning alternative artifacts.

## What I would drop

Seven exposure controls are a lot to learn, especially on a phone. The four guided exposures earn their place more consistently. The minimum-width plate needs horizontal scrolling on small screens; native selection and direct source inspection are more useful there than the spatial comparison. The full source bank is valuable for audit but much larger than the 40 curated excerpts.

## What I would do next

Give a fresh reader the plate and an ordinary package diagram with identical facts. Ask them which code the CLI still uses, which tests actually moved, and whether copied text means unchanged behavior. Observe their explanations without scoring them.

## Visual-variable legend

| Channel | Factual meaning | Limit |
| --- | --- | --- |
| Column position | Base CLI → head CLI → head daemon source | These are source stations, not three simultaneously running systems. |
| Row and family | One file, grouped by its new package directory | Each plate is a defined subset: 43 new production files or 37 moved mechanism tests. |
| Band length | Count of nonblank lines outside import declarations, kept in source order | A minimum hairline preserves tiny/import-only files. Length is not risk or importance. Physical line counts appear in the inspector. |
| Cyan fill | Exact matching retained source lines | Production compares base↔CLI and CLI↔package separately; tests compare base CLI↔package. Import declarations and blank lines are omitted; inline imports/re-exports remain. Equality is textual, not semantic. |
| Pale dotted arrow | Git-detected path movement | On the production plate this marks the coordinator rename within CLI. On the test plate it spans the empty CLI station for 37 moves. Rename similarity is not coverage. |
| Magenta rim | A newly added source owner in the package | New ownership can surround copied text. A new source file can wrap inherited behavior. |
| Amber rail | Relative value-import/export and literal entry-URL reachability from `apps/cli/src/cli.ts` | This is a static graph, not an executed request. It does not traverse package aliases or evaluate arbitrary dynamic import expressions. |
| Dashed retained-CLI enclosure/underline | Membership in the 38-file compatibility inventory | Compatibility-only describes ownership during staging. Those files can remain active. The digest freezes head source, not equality with base. |
| Green dots | A test source directly imports the production file, including type imports | The inventory covers inspected CLI/package test sources. Blank does not mean untested. Dots are absent on the moved-test plate and never imply passing tests or line coverage. |
| Violet hatching | The file participates in a named rationale gap | Authored association, not a computed amount of unexplained code. Gaps in metadata/lint/runner files remain in open readings 01, 07 and 09 outside the plate’s specimen sets. |
| Exposure and sliding film edge | How much of one evidence category the reader sees | Reader-controlled optical visibility only. Neither opacity nor combined color measures confidence, probability or correctness. |

The important compounds are cyan fill inside a magenta rim (**copied text, new source owner**), an amber rail inside a dashed enclosure (**active compatibility graph**), and test dots under violet hatching (**test source exists, rationale remains missing**). Shape and texture preserve distinctions when colors overlap.

## What this form teaches better and worse

The repeated silhouette makes a huge addition readable as **a second location for existing mechanisms**, while its retained middle column prevents the mistaken conclusion that production use moved too. The test plate’s empty middle column makes an actual move visibly different from a copy. Independent films let a reader see that ownership, activity, test-source presence and rationale can coexist instead of being exclusive node colors.

A conventional package diagram would explain a single call chain faster. This plate makes small client files look physically small even though their boundary is consequential, and source length cannot tell a reader how difficult a change is. The nine open readings carry reasons, deferred behavior and deleted assertions that optical membership alone cannot express. Dense source bands also require selection to identify individual files. Those are real limits of the form.

## Regeneration

Reading the artifact requires none of these commands. With the supplied pinned worktrees and their installed TypeScript still available:

```sh
cd ~/projects/rich-review-v2/experiments/77-forensic-light-table
npm run capture
node scripts/verify.cjs
```

`capture` reads only the supplied inputs/worktrees and writes this experiment’s evidence. To rerun browser checks, start `npm run serve` in another terminal and run `npm run check`. Set `LIGHT_TABLE_PLAYWRIGHT` to an installed Playwright package path if `/tmp/rich-review-05-browser/node_modules/playwright` is unavailable. Checks use installed Google Chrome. The pinned renderer can be restored with `npm ci`; reading uses the already-vendored copy and needs no install.
