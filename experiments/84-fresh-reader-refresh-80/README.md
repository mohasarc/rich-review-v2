## Declared choices

- Role framing: a reader reporting what a page taught before seeing its underlying diff, then an editor checking omitted distinctions.
- Box lenses: static package ownership, runtime/process boundaries, authority, lifetime and failure/observation boundaries. A box name is insufficient when its outcome changes.
- Opening style: a labelled lossy procedure sketch followed by the main findings and methodological limits.
- Shape: one long comparison table; all rows form the stopping layer, with source/route receipts below the same claims.
- Navigation: linear table; page/capture/source links; local search, subject filter, and direct-witness filter; return links from receipts. No storage or review actions.
- Trust posture: sealed page-only recall, pinned historical revisions, explicit source-only versus witnessed-descent findings. No correctness verdicts, ranks or completeness certificates. Capturing a page is not counted as reading all of it.
- Persona: one sequential agent reader with accumulating knowledge, not a set of independent humans. Earlier critique exposure is disclosed.
- Representations used: comparison table, short procedure diagram, exact parent/child quotations, numbered pinned source excerpts, machine-readable inventories and hashes. Two retained screenshots show the 52/59 stopping registers; they do not measure comprehension.
- Importance rule: prioritize new authority, failure outcome, default/context distinction, ordering exception, side effect, changed test observation and incorrect absence-of-rationale claims. Preserve declared narrow scope; do not turn every out-of-scope fact into a surprise. Test changes have the same explanatory weight as architecture.
- Inputs used (beyond bundle): earlier experiment README entry/subject metadata and rendered teaching pages; narration text for 21; immediate `inputs/pr-127`, `inputs/pr-131`, `inputs/pr-148` diffs/PR metadata; pinned `git show` source and `plans/005/daemon-policy.md` from the allowed stack worktree; read-only worktree instructions; generated #146/#147 diffs. The large patches received inventories and focused body/test checks, not a complete line-by-line audit. No web sources.
- Tech: dependency-free Python for inventories/source receipts and report generation; Markdown/JSON; standalone HTML/CSS with small local filtering JavaScript; Playwright for reading surfaces, selected routes and artifact verification.
- Built on earlier experiment(s): read 01–37, 40, 49's four variants, 50–53's teaching surfaces, 59's archived pair, and 61–79. The compared content is cited, not reused as this artifact's UI or findings without attribution. Page 50 embeds prior critique; opening 57 exposed a report, which was then classified report-only. Other earlier critique reports/reader notes were ignored. Evidence/source viewers and kit scaffolds were not counted as additional lessons. Full accounting is in [the method](evidence.html#reading-protocol-and-limits).

The table preserves those reading limits per row. It is a broad selective reading, not every control state or a full diff audit.

The initial intention to avoid all earlier critique content failed when 50 embedded it and 57 turned out to be a prior review table. The table therefore reports learned decisions and misses, not comparative comprehension results.

The clearest operated rule-4 witnesses are optional host policy in 23 and the standalone-clock/authentication/host-policy additions below 29's decision map. The four 49 roots document selected repairs and remaining omissions without being counted as independent route trials. Source-only checks separately expose earlier worker validation, later completion-error provenance, concrete test-stimulus changes and a recorded export-retirement condition. Rich #127 parents already disclose the cache/release distinctions checked here.

Validation checked all 70 rows against the frozen captures, the unchanged recall seal, source receipt hashes, local links/anchors, the single-table structure and required README headings. The browser opened the report through `file://`, exercised search/subject/witness filters and reset, followed a receipt anchor, and checked the narrow viewport without page overflow or script errors. Results are in [validation.json](validation.json) and [browser-validation.json](browser-validation.json). These checks do not test Symnav behavior or reader comprehension.

## What I would drop

Independent-reader language for this sequential pass; automated capture volume as a proxy for understanding; a pass/fail completeness score; and treating the video, a narrow model, or a matching-text pair as a complete experiment on comprehension. The initial plan to make this wholly critique-blind was abandoned once that became untrue.

## What I would do next

Use genuinely independent readers on the exact frozen 23/29 original/revised roots, ask outcome/authority questions before descent, and retain the same prompts after source exposure. Expand the source audit only where those answers expose a specific unresolved choice.
